# 资产目录方案（2026-11-01 立）

> 目的：把散落的解包产物按层归类，**保证同一份游戏内容在磁盘上只有一处**，并且脚本不再各自写死目录。
> 现状入口：`D:\BrainMaker\大镖客2解包分析`（411 GB）。本文是目录归属的唯一真身。

---

## 0. 一句话

**源只存一份 · 池可随时重建 · 产物可重复生成但很贵。**
删东西之前先问「它属于哪一层」——源层删了要重抽，池层删了重跑生成器，产物层删了要重做几小时。

---

## 1. 为什么要立这份方案

| 症状 | 数字 | 根因 |
|---|---|---|
| 解包目录比游戏本体还大 | 411 GB vs 119.6 GB | 同一批资源被不同子项目各抽了一遍 |
| 重复副本 | **138 GB**（全库同名同大小，MD5 抽验 40/40 一致） | 没有层归属，谁需要谁抽一份 |
| 脚本互相踩路径 | 16 个脚本写死 `work/lib_gtxd/txd` 等目录 | 目录语义没定死，路径散落 |

---

## 2. 三层定义

| 层 | 定义 | 内容示例 | 唯一性 | 删了会怎样 |
|---|---|---|---|---|
| **源 source** | 从游戏 RPF 解出来的原始文件 | `.ydr .ydd .yft .ytd .ybn .ymap .ytyp .ycd` | **每份内容只允许一处** | 要重抽（需游戏本体 + 1~3 小时/批） |
| **池 pool** | 从源派生的**扁平查表目录**（同名去重、按名直取） | `lib_gtxd/txd`、`tdx_all`、`ydd_all` | 可重复生成 | 重跑生成器即可 |
| **产物 product** | 解析/转换/装配的结果 | `.mdl .png .glb .blend .json .csv` | 每份唯一 | 重建成本高（分钟到小时） |

**判据一句话**：这个文件在游戏包里能找到同名的吗？能 → 源；不能但能从源推出来 → 池或产物。

## 4. 五条规则

| # | 规则 | 说明 |
|---|---|---|
| R1 | **源层唯一** | 新解包落盘前先比对：已有同内容 → 不落。判据 = 文件名 + 字节数，抽样 MD5 复核 |
| R2 | **池层不手改、不备份** | 池是派生视图，随时可从源重建；要改就改生成器再重跑 |
| R3 | **路径统一解析** | 脚本不许写死目录，一律走 `tools/asset_paths.py` 的 `SRC / POOL / PRODUCT` 常量 |
| R4 | **新建目录先问** | 任何新目录先取得用户同意（`docs/AGENTS.md` §1.9） |
| R5 | **删前给清单** | 删除只给命令与影响面，由用户执行；源层删除必须有"重抽成本"说明 |

## 6. 引用统一

B0 阶段**不需要改任何引用**：补缺口的两个落点（`txd_all` / `_missing`）本来就在各脚本的扫描目录里。

到 B2 才新增 `tools/asset_paths.py`，那时才有引用方。设计（先定，别提前建空壳）：

```python
from asset_paths import SRC, POOL, PRODUCT

SRC      # raw/          源根
POOL     # raw/lib_gtxd/ 池根
PRODUCT  # assets/ + export/ + deliverable/
```

**迁移纪律**：一次只改一类脚本，改完立刻跑该脚本的验收；**不做"批量替换"**。
未迁移的脚本保持原路径不动 —— 因为池层目录在迁移期间**一个都不删**。
