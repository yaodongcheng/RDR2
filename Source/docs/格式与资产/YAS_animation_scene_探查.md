## 1. 容器结构（已确认）

`.yas` 与 `.ymt` 同族，是 **PSIN** 容器，节表如下（`tools/parse_pso.py` 可直接读）：

| 节 | 含义 | 说明 |
|---|---|---|
| `PSIN` | 实例数据 | 真正的对象数据，大小差异极大 |
| `PMAP` | 根结构 + 条目表 | 每条 = {结构名哈希, 偏移, 长度} |
| `PSCH` | 结构定义 | 每个结构的字段列表（字段名是 joaat 哈希） |
| `PSIG` | 签名/校验 | — |
| `STDN` | 标准名表 | 264~1640 字节 |
| `CHKS` | 校验和 | 20 字节 |

实测两个样本：

| 文件 | 总大小 | PSIN | PMAP 条目 | 结构数 |
|---|---|---|---|---|
| `ig_1_arrival_dutch.yas` | 12.9 KB | 2.2 KB | 14 | 17 |
| `ig_13_barn_brawl.yas` | 57 KB | 30.4 KB | 23 | 25 |

> **结论**：`.yas` 不全是小文件；大文件里 PSIN 有 30 KB，足够放镜头表，值得继续挖。

## 2. 哈希函数（已确认）

`PSCH` 的字段名是 **joaat（FNV-1a 变体，小写化）**：

```python
def joaat(s):
    h = 0
    for c in s.lower().encode():
        h = (h + c) & 0xFFFFFFFF
        h = (h + (h << 10)) & 0xFFFFFFFF
        h ^= h >> 6
    h = (h + (h << 3)) & 0xFFFFFFFF
    h ^= h >> 11
    h = (h + (h << 15)) & 0xFFFFFFFF
    return h
```

用 2 278 个候选名撞 `ig_13_barn_brawl` 的 135 个字段哈希，命中 **8 个**：

```
Clip   Entity   Ped   Rate   Flags   State   Value   Scale
```

命中率远超随机（32 位哈希，2 278×135 次比较的随机碰撞期望 ≈ 0.07 个），
**说明哈希函数正确**，只是 RDR2 的 yas schema 用了我们没猜到的名字。

> 字段名在这批结构里明显是「场景对象」的语言（Entity / Ped / Clip / Rate / State / Flags），
> 与「一个 scene 里每个对象指定 clip、播放速率、状态」的模型吻合。

## 3. 已排除的思路（别重踩）

| # | 思路 | 结果 |
|---|---|---|
| 1 | 在 `.yas` 里搜 clip 名的字符串 | **0 命中**（`.yas` 几乎是纯二进制，只有 padding 的 `pppp`） |
| 2 | 搜 clip 名的 joaat 哈希 | **0 / 813** 命中 → 场景**不按 clip 名引用** |
| 3 | 直接用 `parse_pso` 读根结构字段 | 根结构 `00000006` @ `0x130` 字段数 0（是个空/占位结构） |
| 4 | 4800 字节块按「每行一镜」找时间列 | 字节自相关定出 **stride=160**、共 **30 条**；逐字段检查 **无单调时间列**，也无 timeish 浮点列 |

第 4 条的细节（`ig_13_barn_brawl`，`PMAP` entry #6 @ `0x880`）：

```
stride = 160 字节，条目数 = 4800/160 = 30
24 个字段（偏移 0x008 ~ 0x094）
```

30 条 × 24 字段里没有任何一列像「起始时间/时长」，说明时间轴不是这个结构，
或者时间被编码成「帧索引/量化值」而非秒。

## 13. 更关键：`.yas` 的变换不是普通浮点

拿两个大场景（`ig_13_barn_brawl` PSIN 30 KB、`leadin@mcs2` PSIN 36 KB）扫描：

| 检查项 | 结果 |
|---|---|
| 单位四元数（x²+y²+z²+w²≈1 的连续 4 个 float） | **0 个** |
| 三轴都非零、量级 <5000 的坐标三元组 | **0 个** |

说明 entity 变换是**量化编码**（定点/整数）存的，不是 IEEE float。
**没有 RDR2 的 PSIN/yas schema，就读不出来** —— 这不是"有文件就能解"的问题。

### 因此「角色初始站位」的准确卡点

1. 过场本体的 `.yas` 不在本地（游戏目录也不在）
2. **即使拿到**，还要有 schema 才能解量化变换

这两条都在外部（游戏文件 + CodeWalker 级 schema），本地无法推进。
