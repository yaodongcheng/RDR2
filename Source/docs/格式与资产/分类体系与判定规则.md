# 分类体系与判定规则（唯一入口）

> 读者：接手分类/区域检查的人。结论先行；要改分类，先读完这一页。
> 代码真身：**`tools/class_rules.py`**（类表 / 隐藏表 / RULES / LEFTOVER / ROAD / RUIN / 纠错解析 / 判定函数）· `tools/veg_rules.py`（植被词表）。

> 改完必须跑 `python tools/_check_rules.py`（合法性 + 冗余 + 用例回归）。

## 2. 判定顺序（从先到后，命中即停）

```
terrain_lod → lod → terrain_cell → underground → watertile → placeholder
→ rail_decal → rail → struct → road → ruin → decal → veg → stone → rock
→ veh → bldg → part → junk → prop
→ （前面全没中）LEFTOVER: road → decal → prop
→ （仍是 unknown 且平/薄/大/贴地）decal
→ 贴花证据：`_dc` / `_dec` / `_det_dec`（含 unknown 的 `_d`）+ albedo 半数以上是污渍 → bldg_decal（地面语境 → decal）
→ 布局白模：整件贴图全是 `layout_*` → layout（默认隐藏，不删网格）
→ 纠错清单（CSV）
→ 贴图兜底：仍是 unknown 且贴图名带 `_lod` → lod
→ 硬规则：ruin → junc→road（junc 最后，优先级最高）
```

### 2.1 贴花证据（2026-11-06）

- **为什么不能只按后缀**：48 个 `_dc` 名字里有 5 个是真建筑（`her_01_shack_01_dc` 用木墙贴图），一刀切会把真房子藏掉。
- **判据**：名字带 `_dc` / `_dec` / `_det_dec`（任意类），或仍是 `unknown` 的 `_d`，且模型 albedo 槽**半数以上**命中污渍词（`overlay|decal|_dc_|grime|grunge|rust|stain|moss|dirt|mud|poster|splatter|drip|puddle|smudge|nails|woodchip|scratch|signs?_notices|branding`）→ `bldg_decal`；名字带地面语境（river/scree/road/street/path/ground/mud/track/trail/sand/snow）→ `decal`。
- **放在纠错之前**：纠错清单是人工裁定，必须能覆盖它。
- **不动 `_dcl`**：`_dcl` 走原有纯名字规则（2026-11-05 已验证）。
- 实现 = `class_rules.apply_texture_decal()`；用例在 `tools/rules_cases.csv`（含反向用例 `her_01_shack_01_dc` → `bldg`）。

三条硬规则（写在 `classify_entities.py` 尾部，纠错之后执行）：

1. 名字含 `ruin` 且不是 `lod/underground` → **ruin**；
2. 名字含 `junc` → **road**（没有例外，`lod/underground` 也照样改）；
3. 纠错清单里 `lod/underground` 是**技术类豁免**：内容纠错不覆盖它们（`junc` 硬规则除外）。

**为什么先铁路**：`railroadtie`（枕木）也含 `tie`，`_r_c_` 地块会被 `part` 的 `wall` 抢走。
**为什么 road 在 decal 前**：路面/路口要单独成类；decal 只留血迹/落叶/污渍。
**为什么 ruin 在 stone 前**：`ruin_stone` 否则会被 stone 吃掉。

## 3. 判定来源（四条，优先级从高到低）

### 3.1 硬规则（代码）
见上。只用于“用户明确要求、不允许例外”的类：`ruin`、`junc→road`。

### 3.2 名字正则（`RULES` / `LEFTOVER` / `veg_rules`）
- 名字来自 `names.txt`（29.4 万条 hash→名字）；查不到的名字显示为 `e_<hash>`。
- `RULES` 是主表，**书写顺序 = 优先级**；`LEFTOVER` 只对前面全没中的对象生效。
- 植被词表在 `veg_rules.py`；`VEG_EXCLUDE` 是“长得像植物的道具”，先判排除再判 VEG。

### 3.3 几何兜底
- **地下停放**：`tag=parked_offmap`，或“占地范围 9 点取最低地形，比对象最高点高 10 m” → `underground`。
- **地面贴花**：平、薄、大、贴着地面（`is_ground_decal`，读 H4 高度）→ `decal`。

### 3.4 贴图匹配（纠错清单的 `texture_pattern` 列）
- 匹配对象**材质名**（`alb_<贴图名>`）；对账脚本用 `index.json` 的完整贴图列表（manifest 的 `t` 只存前 4 个）。
- 当前生效的两条：
  - `^e_` + `kudz[uo]` → veg（无名葛藤）
  - `road_muddyroad|hea_track_decal|sca_road_mud` → road（名字无线索的泥路/车辙片）

## 4. 纠错清单（区域检查期的临时规则）

文件：`D:\BrainMaker\大镖客2解包分析\deliverable\blender\regions_support\region_corrections.csv`

| 列 | 说明 |
|---|---|
| `id` | 递增编号，日志里会打印 |
| `pattern` | 对象名正则（可空） |
| `texture_pattern` | 材质/贴图名正则（可空） |
| `target_class` | 目标类 |
| `reason` / `status` / `date` | 给人看 |

**语义**：`pattern` 或 `texture_pattern` **任一命中**即生效（两列都填是“或”，不是“与”）。命中后压过名字规则/几何兜底，但 `lod/underground` 除外。

用法：
- 区域裁剪：`blender -b <region.blend> -P tools/_apply_corrections.py -- --corrections <csv> --out <同一 blend>`（约 3~5 分钟，不重建几何）
- 正式构建：`blender_continent.py --corrections <csv> ...`
- 对账：`python tools/_check_region.py --tile <tid> --audit <manifest jsonl>`（会把同一份清单应用到 v23 侧）

**转正**：区域检查结束后，把稳定的条目改写成 `class_rules.py` 里的内置规则，CSV 只留临时条目。

## 6. 改分类的标准流程

1. 改 `class_rules.py`（内置规则）或加**纠错行**（区域检查期，`region_corrections.csv`）；
2. `python tools/_check_rules.py` —— 合法性 + 冗余 + `tools/rules_cases.csv` 用例回归；
