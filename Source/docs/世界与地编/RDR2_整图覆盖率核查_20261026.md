## 1. 口径先说清楚（否则数字对不上）

| 名词 | 含义 | 数量 |
|---|---|---|
| **实体 / 实例** | ymap 里摆在世界上的一个物件（`town_data/*.js` 去重后） | **182 158** |
| **archetype** | 实例引用的"原型"（hash）。一个 archetype 可被摆多次 | 唯一 **101 185** |
| **model** | 解出来的网格（`assets/lib_native`，key 是 model hash） | **52 539** |
| **可命名 archetype** | 能在 `names.txt` 反查出名字的 | **51 407**（50.8%） |

> ⚠️ **关键陷阱**：`tiles/*.json` 里存的是 **archetype hash**，`lib_native` 的 key 是 **model hash**。
> 两者只在"archetype 名 == model 名"时才相等。所以**不能直接拿 hash 求交集来算覆盖率**，那会系统性低估。
> 本文的分类覆盖率按「能反查名字的 archetype」分组统计，未命名单列。

## 3. 真缺口 = 那 5 万个「未命名」

### 3.1 为什么没解出来

工作流是「archetype hash → 用 `names.txt` 反查名字 → 按名字找 `.ydr` 抽网格」。
`names.txt` 只有 294 471 条，**49 778 种 archetype 反查不到名字** → 找不到对应资源 → 没进模型库 → blend 里就是空的。

**这不是"故意不装"，是"没认出来所以没抽"。**

### 3.2 它们在哪、有多大

| 维度 | 数字 |
|---|---|
| 未命名实例总数 | **50 007** |
| 其中 ≥8 m 大件（cls 3） | **44 900** |

| 落在主要活动区（x −3000~3000, y −2500~2500） | 14 599 |
| z < 0（水下/地图外补地） | 4 087 |
| z < 50（山地/水面） | 13 422 |

**据点内未命名大件 TOP 8**（严格框，米）：

| 据点 | 未命名大件 | 大件总数 | 占比 |
|---|---:|---:|---:|
| sdn 圣丹尼斯 | 2 124 | 4 884 | 43% |
| ann 安尼斯堡 | 308 | 564 | 55% |
| bla 黑水镇 | 291 | 561 | 52% |
| val 瓦伦丁 | 267 | 557 | 48% |

| cal 卡利加种植园 | 193 | 440 | 44% |
| bra 布雷斯韦特庄园 | 143 | 314 | 46% |

> 圣丹尼斯 43% 的"大件"未命名，基本可以确认是 **RDR2 城市建筑的模块化部件**（墙段、屋顶片、檐口、阳台），
> 这些部件的名字很多不在社区版 `names.txt` 里。**不等于楼没了**，但确实存在部件级缺失。

> **"有名的房子基本都在；把一栋楼拼起来的那堆无名零件，有四成没装。"**

## 5. 「用贴图就卡死」的根因

| 项 | 量级 |
|---|---|
| `continent.blend` | **8.37 GB** |
| 装进场景的对象 | **128 627** 个 instance 对象 |
| 唯一网格 | ~10 000+ |
| 贴图 | **7 065 张 / 2.4 GB**，`_mat_for()` 逐材质 `bpy.data.images.load()` |
| 地形地面彩图 | **12 296² 或 24 592²**（单张 0.23 / 0.81 GB） |

**卡的不是模型，是"每帧给 12.8 万个对象绑定 7 千张贴图"**。
Solid 模式不采样贴图 → 不卡；切 Material Preview / Rendered → 立即卡死，符合你的现象。

### 优化档位

| 档 | 做法 | 效果 | 代价 |
|---|---|---|---|
| **A 立刻可用** | `tour.solid()` | 立刻流畅 | 看不到贴图（看体块/找缺失足够） |
| **A+** | `tour.shrink_textures(256)` | 贴图内存 ~2.4 GB → ~0.3 GB | 贴图变糊；不写回文件 |
| **B 局部加载** | `tour.tileify()` + `tour.only(tid)` | 同屏对象降到 1/43 | 一次只能看一块 |
| **C 只看建筑** | `tour.hide_small(1.5)` | 关掉约 8.7 万小物件 | 丢可捡道具 |
| **D 根治** | 贴图降采样 + 按 43 块拆成独立 blend | 单块秒开 | 要重跑装配（数小时） |

> **看"有没有缺建筑"的最优路径其实不是 Blender**：
> `预览沙盒地图.bat` → `miniatures/map/index.html` 是 46 据点的微缩模型，**同屏 23.5 万面 / 47 draw call**，秒开。
> 先用它扫一遍哪里空，再回 `continent.blend` 用 `tour.jump()` 精准核对。

4. 重跑装配：`blender -b -P tools/blender_continent.py -- --out <blend> --lib assets/lib_native --rails`

### 8.3 修掉的地形对齐 bug（重要）

**症状**：willard 首版渲染出来是一片土色，房子完全看不见。

**根因**：`export/levels/world/settlements_bannerlord.csv` 里三个剧情点的 `u,v` 是 `0,0`：

| code | 名称 | 错误 u,v | 正确 u,v |
|---|---|---|---|
| hso | 马掌望台 | 0, 0 | 521.2, 285.1 |
| abe | 阿伯丁猪场 | 0, 0 | 654.3, 288.1 |
| roc | 威拉德之息 | 0, 0 | 736.1, 131.8 |

`blender_continent.py` 的 PAD（地块压平）靠 `world = -7684 + u*14.5 / 4100 - v*14.5` 定位据点，
u/v=0 被算成地图西北角 → 这三片**从没被压平** → 地形比建筑高 6~9 m，房子被埋。

**实测（willard.blend，334 个对象）**：

| 指标 | 修正前 | 修正后 |
|---|---|---|
| 建筑底 − 地形 中位差 | **−5.92 m** | +3.59 m |
| 被地形埋住（< −0.5 m） | **303 / 332** | **8 / 335** |
| 房子附近差值 | −8.4 ~ −9.9 m | +0.1 ~ +1.9 m |

> `settlements_bannerlord.csv` 已修正（有备份）。`willard.blend` 已用修正后数据重建。
> **`continent.blend` 仍是修正前的数据**，全图需要重跑一次装配（约 15 分钟）才能生效。
