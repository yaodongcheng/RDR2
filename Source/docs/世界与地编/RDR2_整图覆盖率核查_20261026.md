## 1. 口径先说清楚（否则数字对不上）

| 名词 | 含义 | 数量 |

## 5. 「用贴图就卡死」的根因

| 项 | 量级 |
|---|---|
| `continent.blend` | **8.37 GB** |
| 装进场景的对象 | **128 627** 个 instance 对象 |
| 唯一网格 | ~10 000+ |
| 贴图 | **7 065 张 / 2.4 GB**，`_mat_for()` 逐材质 `bpy.data.images.load()` |
| 地形地面彩图 | **12 296² 或 24 592²**（单张 0.23 / 0.81 GB） |

**卡的不是模型，是"每帧给 12.8 万个对象绑定 7 千张贴图"**。
Solid 模式不采样贴图 → 不卡；切 Material Preview / Rendered → 立即卡死，符合你的现象。

### 优化档位

| 档 | 做法 | 效果 | 代价 |
|---|---|---|---|
| **A 立刻可用** | `tour.solid()` | 立刻流畅 | 看不到贴图（看体块/找缺失足够） |
| **A+** | `tour.shrink_textures(256)` | 贴图内存 ~2.4 GB → ~0.3 GB | 贴图变糊；不写回文件 |
| **B 局部加载** | `tour.tileify()` + `tour.only(tid)` | 同屏对象降到 1/43 | 一次只能看一块 |
| **C 只看建筑** | `tour.hide_small(1.5)` | 关掉约 8.7 万小物件 | 丢可捡道具 |
| **D 根治** | 贴图降采样 + 按 43 块拆成独立 blend | 单块秒开 | 要重跑装配（数小时） |

> **看"有没有缺建筑"的最优路径其实不是 Blender**：
> `预览沙盒地图.bat` → `miniatures/map/index.html` 是 46 据点的微缩模型，**同屏 23.5 万面 / 47 draw call**，秒开。
> 先用它扫一遍哪里空，再回 `continent.blend` 用 `tour.jump()` 精准核对。

三条独立证据都指向「LOD 合并块」：

1. **来源**：46,532 个（92.9%）定义在 `*_lod_combine_metadata*` 里；
2. **尺寸**：bbox 最大边中位 **64.0 m**、P90 **128.0 m** —— 整块瓦片，不是零件（真件中位 7.4 m）；
3. **空间重合**：抽 3,001 个未命名实例，**2,325 个（77.5%）水平 <0.5 m 内就有一个已装好的具名件**
   —— 它们盖在真几何上面，正是 LOD 该在的位置。

又因为 `name == assetName`（§10.1）、包里也没有对应条目（§10.2），所以
**这批实例在磁盘上根本没有独立资源**：游戏在运行时按子 archetype 现场合并出这一层远景 LOD。

### 10.4 结论与验收口径（取代 §0/§7 的旧说法）

### 10.5 顺带修掉的一个真 bug：`index.json` 的 key 没补零

`dump_model_lib.write_model()` 以前用 `hex(h)` 生成文件名/键 —— `hex()` **不补零**，
于是 index 里同时存在 `0x4ac59bc` 与 `0x04ac59bc` 两种键：

| 实测 | 数 |
|---|---|
| 非规范 key（应为 `0x`+8 位） | **3,430 个** |
| 其中"只有不补零那个键"→ 构建时按 `'0x%08x'` 查不到 | **367 个模型** |
| 修复 | `tools/normalize_lib_index.py`（以磁盘 `.mdl` 为准重建 index）+ `write_model` 改成 `'0x%08x'` |

这 367 个模型是"库里有、场景里没有"，属于最高原则 §6.4 的**复发**（已在 §六 记录）。

### 10.6 顺带找回 1,782 张孤儿贴图（"白块"的真根因）

体检 `assets/lib_native` 时发现贴图侧也有同一类"只存 id 不存名字"的后果：

| 实测（2026-10-29） | 数 |
|---|---|
| `tex/` 目录里的 PNG | **7,074** |
| `index.json` 的 `tex` 表 | **5,292**（id 0..5291） |
| 孤儿（磁盘上有、表里没登记） | **1,782**（id 5292..7073） |
| 引用越界 tid 的子网格 | **71,951 / 221,494 = 32.5%** |
| 因此"一张 albedo 都没有"的模型 | **20,858 个 / 场景 23,099 个实例** |

**为什么这不算"猜"**：`.mdl` 里的 tid 与磁盘文件名是同一代贴图池的编号；
随机抽有源 `.ydr` 的模型做像素比对（解出真实贴图名 → 从池里取图 → 与 `tex/<tid>.png` 逐像素比），
**一致率 5/5**。所以按 id 绑定是**找回原绑定**。

处置：`tools/register_orphan_textures.py` 把 1,782 张按 id 追加进 `tex` 表
（名字用 `tex<id>`，并打 `x:1` 标记说明"名字是 id 派生、非游戏原名"），
再 `postprocess_continent.py --relink` 重挂材质（v9 实测：**71,929 个材质槽**被换回正确贴图）。

> **仍未根治**：`.mdl` 的子网格记录里没有贴图名字段。只要 `tex` 表再被覆盖一次，同样的问题会再来。
> 根治方向已写进 `docs/TODO.md` §0.6。

## 11. 2026-10-29 下午：贴图"根本不是那张图"的彻底重做

§10.6 的孤儿贴图只是**冰山一角**：真正的毛病是 `.mdl` 只存 `tid`，而 `tex` 表被重排/复用过，
`id ↔ 名字 ↔ 文件内容` 三者会互相错位（草坪上贴出一扇门就是这么来的）。这一段是**重做**，不是补丁。

### 11.2 为什么池里没有 —— ytd 在 props 包里，不是只在 `*_txd.rpf` 里

`extract_textures_from_game.py` 的 `--only txd` 过滤只下钻名字带 `txd` 的嵌套包，

| 解析布局 | 除"内联 / 指针数组"外，新增**全表签名扫描**（步长 0xB0 之外还有 0x160 等）；0 纹理文件 2,368 → **2,125** |

### 11.3 重做：名字即真相

- 每个模型 hash 都能在 RPF 索引里找到同 hash 的 `.ydr/.yft`（**55,607/55,608**），
