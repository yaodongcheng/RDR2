## 1. 坐标换算（可直接用）

我方世界坐标 → campaign 单位 → 参考图像素（1400 宽版本）：

```
u = (x - X0) / 14.5          X0 = -7684
v = (YM1 - y) / 14.5         YM1 = 4100

map_px_x =  a*u - c*v + tx   a = 1.7614   c = +0.0062（旋转 +0.20°）
map_px_y =  c*u + a*v + ty   tx = -61.09  ty = -2.83
```

* `a` = 均匀缩放；旋转 ≈ −0.2°（可忽略，官方图**正北朝上**）。
* ⚠️ **最终值来自用户手工标定的 5 个特征点**（`地图下载/配准控制点.csv`）：
  **RMS 1.9 px、最大 3.4 px** —— 说明这张图确实是严格的相似变换，之前的偏差全是我读点不准造成的。
  历史：`1.6767`（按地名文字）→ `1.7188`（按城镇图标）→ **`1.7614`（用户 5 点）**。

## 5. 铁轨 / 道路

### 5.1 根因：铁轨本来就在模型库里，是被我们"当重复地表剔掉"了

`build_entities()` 里有两条剔除规则：

```python
TERRAIN_CELL = re.compile(r'(_r_c_\d+|_rc_\d+|_ground\d*$|_terrain)')   # 当成地表贴片 → 跳过
flat_wide = (dz < 2.0 and max(dx, dy) >= 16) or max(dx, dy) > 45          # 又扁又大 → 跳过
```

而 RDR2 的铁轨资产**正好长这样**：`jklm_7_10_rails_c/jklm_7_10_r_c_01..70.ydr`（道砟+枕木+钢轨的地块）、
`j_710_r_b_sle00..17`（枕木段）、`j_710_r_c_steel00..02`（钢轨）、桥/隧道/栈桥 `j_710_r_b_bri*` `tun` `tres*`。
它们的包围盒又扁又宽，名字里带 `_r_c_` —— **两条规则同时命中，整条铁路被丢掉了**。
所以地表只剩"贴图上画的一条线"，看起来自然"贴得不好"。

### 5.2 已修：整条铁路网装回来 + 贴地

但它们其实都在 `lib_native` 里（只是没被关联）。用 `names.txt`（294,471 条）自建 joaat 表即可反查：

**能做的两件事**：
1. ✅ **提高地面贴图分辨率**（已做）：源数据 `<tile>_t` 是 **2048²/512 m = 0.25 m/px**，

   `terrain_ground` 材质，文件 `deliverable/blender/continent/world_ground_2p0.png`（相对路径 `//`）。
2. ⬜ 手描主干道路生成路面板（几何），才会在近景有真正的路缘/边缘。

### 5.5 官方图自动提铁轨中心线：不可行（已实测）

按"最暗像素"提（铁轨 ≈ 灰 60–100，道路 ≈ 115–145，纸面 ≈ 175–200）→ 形态学连成带 → 按长度过滤，
结果把**州界、道路、地名一起提了出来**（`img/rail_extract_fail.png`）：州界线和铁轨灰度几乎一样，
铁轨真正的特征是"双线 + 枕木横档"的周期纹理，不是亮度。

要自动提只能做"局部自相关找横向周期"，或半自动人工描点。

## 7. 自己标定（3 个点就够）

**3 个点足够**：相似变换只有 4 个未知数（缩放 s、旋转 θ、平移 tx/ty），
2 个点给 4 个方程就能解，**第 3 个点是验算**（残差小才说明标定可信），建议标 4~6 个、分散在四角。

准备的两张带网格参考图：

| 图 | 文件 | 坐标 |
|---|---|---|
| 官方地图（1400 宽） | `img/ref_map_grid.png` | 每 100 px 一条线，边上标了像素坐标 |
| 我方世界俯视（1400²） | `img/ours_grid.png` | 同上；正好覆盖 `x∈[-7684,4612]`、`y∈[-8196,4100]` |

**推荐做法：用取点工具（像素级）**

打开 `http://127.0.0.1:8788/anchor_picker.html`：

* 左右两张图分别加载**高分辨率原图**（官方 5000 宽 / 我方 2048²），不是缩略网格图；
* **滚轮缩放**（最多 12×）、**拖拽平移**，右侧实时显示当前鼠标的**图内像素坐标 + 规范坐标（1400 制，0.1 px）**；
* 左键单击 = 取点：先点官方图，再点我方图同一处，自动配成一对；
* 表格里的数字**可以直接改**；`Shift+方向键` 以 0.1 px 微调最后一对；
* 建议在 **4× 以上**的缩放下取点（1 屏幕像素 ≈ 0.1–0.2 图内像素），点完 `<复制 CSV>`。

> 精度说明：适应窗口时 1 屏幕像素 ≈ 6.8 图内像素（≈2 规范像素），所以**必须放大**再点；
> 放大到 8× 就是亚像素级，配合方向键微调可以做到 0.1 px。

步骤：

1. 在两张图上找**同一个特征点**（河口、湖角、城墙拐角、桥头），记下两边的像素坐标；
2. 填进 `地图下载/配准控制点.csv`：

   ```
   name,map_x,map_y,ours_x,ours_y
   圣丹尼斯河口,1188,660,1010,905
   瓦伦丁桥,805,405,650,905
   罗兹南桥,1012,650,1013,609
   ```

3. 跑：

   ```bash
   python tools/fit_map_anchors.py            # 输出残差 + 写 地图下载/配准结果.json
   python tools/rerender_overlays.py --a <a> --tx <tx> --ty <ty>   # 重画比对图
   ```

   或者一步到位：`python tools/fit_map_anchors.py --rerender`

现在文件里已经填了我读的 4 个点（城镇图标中心），残差 RMS **12.2 px**（≈105 m）——你补/改几个点就能更准。

### 7.1 我另外用「水体形状」自动找了一组点，结论一样

不想靠人工读点的话，我做了个自动版：在官方水体上选**结构最丰富的 4 块**（岸线穿过的地方），
在水体掩码里做块匹配求出对应位置，再换算成控制点：

| 控制点(box 图) | 官方 (map_x, map_y) | 我方 (ours_x, ours_y) |
|---|---|---|
| auto16 | 87.5, 962.5 | 141.2, 920.8 |
| auto0 | 787.5, 262.5 | 796.3, 261.9 |
| auto12 | 787.5, 787.5 | 786.6, 771.0 |
| auto3 | 1312.5, 262.5 | 1317.8, 250.4 |

拟合结果：`a = 1.7217, rot = −0.16°, tx = −51.5, ty = −4.2`，**RMS 14.3 px**。

两组独立的点都指到同一个尺度（1.72），说明尺度已经定了；剩下的 12~14 px 就是
**这张手绘地图自身的不一致下限** —— 无论用哪组点，都不可能把全图压到 10 px 以内。

也就是说：**你给 3 个点，这 3 个点会严格对准**，其它位置最差会有 ~15 px（≈130 m）的残差，
这是地图本身的问题，不是标定没做好。

## 9. 海平面怎么修正（用对齐后的地图 + 地形）

### 9.1 先说结论：这个世界的 z 不是单一海平面

实测（H4 高程 + 水位场）：

| 水体 | 水位 |
|---|---|
| Flat Iron Lake / 东部海岸 | **41.9 ~ 42.8 m** |
| 山地湖（comp74） | **234.2 m** |
| 山地湖（comp90 / comp63） | **148.5 / 88.8 m** |
| 犰狳镇所在洼地 | 地形 **−14.7 m**（**干的**） |
| 风滚草镇所在洼地 | 地形 **−3.3 m**（**干的**） |

所以：**不能"地形低于 41.9 m 就灌水"** —— 实测那样做会把**犰狳镇、风滚草镇整个淹掉**（都在海平面以下但确实是陆地）。

### 9.2 正确做法（已实现）

1. **形状**：用对齐后的官方地图水体（`ref_water_mask_1400.png` 按 `配准结果.json` 反算到世界网格）
   ∪ 原掩码（官方补海/大湖，原掩码补小池塘）；
2. **水位**：按连通域，`level = median(该水体岸线处的地形高程)`；
3. 逐像素写入 `export/world/water_level_map.npy`（NaN = 陆地），再重建 Water 网格。

脚本：

```bash
python tools/water_from_aligned_map.py      # 算水位图
blender -b deliverable/blender/continent/continent.blend -P tools/rebuild_water_from_map.py
```

本次结果：合并水体 **11.2 km²**，重建 **298,838** 个水面四边形（只保留被引用的顶点，无 NaN 顶点）；
水面高程 **中位 42.1 m、范围 −4.0 ~ 241.4 m** —— 山地湖终于在 234~241 m 的高度上出现了
（以前统一按 42.8 m 铺，整片沉在地下看不见）。

备份：改动前的文件是 `continent_prewater.blend`。
