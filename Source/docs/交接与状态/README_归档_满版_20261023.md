### C. 技术结论（踩过的坑，别重来）

1. **过场必有上下黑边**（按片高 2.5% 判），可用作"过场/操作"分类。
2. **硬切 = 相邻帧归一化互相关骤降到 <0.32**；运镜不会（实测 gdiff 12.3 而 gNCC 0.875）。
3. `.yad` **按页存储（单页上限 16 s）**；同一页内所有动画时长一致；clip 结构体里的时长 == 所在页时长（155/155 命中）。
4. **`.yad` 是未剪辑的 take 素材**：分页时长求和远大于过场总长（`wnt1_mcs2` 85.7 s vs 38.8 s）；素材节奏中位 6.43 s vs 录屏实测 3.75 s。
5. **`.ycd` 有「名字 → 时长 → 所在分页」，但没有顺序**；`.yad` 里没有名字哈希。
6. **`.yas` 不含时间轴**（f32 秒列仅 42 个值、u32 毫秒单调游程全是零填充），且 entity 变换是**量化编码**（单位四元数 0 个）。
7. 任务脚本里的 5 个数字是 `Stack.Invoke` 的**命令 ID**，不是时间；但脚本里有**官方过场播放顺序**（已提取 72 个任务）。
8. `.ycd` 文件名 **不等于** 过场 ID（`wnt1_int_cabin.ycd` → `wnt1_int_col`），要从 clip 名反推。

### D. 关键技术结论（别重新踩）

1. **`.ymt` 是 PSO/PSIN 格式**（大端；节 = `tag(4)+len(i32)+payload`，节序 `PSIN/PMAP/PSCH/STDN/PSIG/CHKS`）。

**相机编码（实测，踩过坑）**

- 相机 = 小骨架（5/15/21 骨）、**5 根轨道 = [posX, posY, quatW, quatX, quatY+Z]**
  —— 第 3 个通道 ≈ `sqrt(1-|q|²)`，是四元数 w，**不是坐标 z**（一开始当 z 用，数值对不上才发现）
- 段内位移 0 = 固定机位；>0 = 运镜（样例 `brt1_mcs2` 两段分别 0.65 m / 1.48 m）
- 同一过场里多个固定机位、位置只差 1~2 米 → 多半是**同一段表演的多个 take**，不是剪辑分镜
  （分镜号在 clip 名里：`exportcamera_wnt1_mcs2_p2_t03_shot_1..4`）

**跨页拼接（本轮的关键突破）**

`.yad` 按页存，单页最多 16 秒；直接按页解码只能拿到碎片（实测大量过场时长卡在 16.0 s）。
把「上一页末位姿 == 下一页首位姿」的节点接起来后，过场恢复完整长度：

| 过场 | 拼接前 | 拼接后 |
|---|---|---|
| `brt1_mcs2` | 16.0 s | **24.87 s** |
| `wnt1_ext` | 16.0 s | **33.07 s**（3 个 take × 11.02 s） |
| 全量 | 65.9 分钟 | **73.1 分钟** |

工具：`tools/cutscene_camera_stitch.py`（`--all` 全量，约 3 分钟）。
452 个过场里 **105 个是单链**；链长用该过场的已知时长（结构表）截断，避免把「同一机位在多页重复」串成超长链（`bou1_mcs1` 曾因此虚高到 112.7 s，截断后回到 32.1 s）。

**`.ycd` 字典进展（本轮新查到的）**

- clip 名的 **joaat 哈希确实存在 `.ycd` 里**（`joaat("cs_dutch_face_wnt1_mcs1_p1a1_t06_shot_1") = 0x2fd28bb7`，文件里命中）
- 条目形态：`{name_hash, ptr → 0x50000350 之类的结构, ...}`，条目里**没有**帧数/时长字段
- `.yad` 里**不含任何名字哈希**（le/be/高位/移位四种变体都试过），是纯动画数据 —— 所以「名字 ↔ 数据」只能通过 `.ycd` 的指针链解，需要按 YCD v2 布局逐字段推

**录屏校验（本次做的量化对照）**

只看「有黑边的过场」这一部分，比较剪辑节奏（每分钟镜头数）：

| 来源 | 过场镜头 | 过场时长 | 镜/分钟 |
|---|---|---|---|
| 资产侧（653 个过场） | 2 156 | 314.8 分钟 | **6.85** |
| 录屏侧（35 分钟样本） | 114 | 18.8 分钟 | **6.06** |
| 差异 | | | **13%** |

→ 两边剪辑密度同量级，说明「按 clip 名数镜头」这个口径基本合理。
结果落到 `export/story/cutscene/validation_video.json`；逐段明细（录屏段 → 最近资产过场：镜头数/时长/每镜时长）见 `video_shot_timing.json`。

**`.yas`（animation scene）探针**

- 同一个过场包的 `.yas` 大小差别很大：`ig_1_arrival` 只有 12.9 KB（PSIN 2.2 KB），
  `ig_13_barn_brawl` 57 KB（PSIN 30.4 KB）
- 大文件里有 4 800 字节、24 字段的结构块（`PMAP` entry #6 @ 0x880），疑似场景对象/轨列表，**尚未解出语义**
- 字段名哈希用 `names.txt` 只命中 1/94 → 需要专门的名字表才能解 schema
- `.yas` 里搜不到 clip 名的 joaat（813 个候选全落空）→ 场景不按 clip 名引用

**还没解通的（下一步）**

`.ycd` 字典条目（`{ptr, count, name_hash, ...}`）尚未解出「clip → 帧数/数据偏移」映射，导致：
- 每镜时长拿不到（现在只有整段时长 + 镜头数；相机段里混着多个 take）
- 相机段无法一对一绑到 `shot_N`（`exportcamera_..._t03_shot_2` 这种名字拿不到对应数据）

**已知规律**：一个过场的相机块里，常出现「同一组镜头重复 N 遍」= 同一段表演录了 N 个 take
（例：`fin1_int` 段长 `0.4 / 2.5 / 1.9 / 5.63` 重复两次；`wnt1_ext` 11.02 s 重复三次）。
所以「段数 ≠ 镜头数」，要落到分镜必须解出 `.ycd` 的名字↔数据映射。

## ★ 录屏反拆解（2026-10-23 · 从一条样本学到可复用规则）

**一句话**：给一条带字幕的主线录屏，自动拆出**镜头表 / 过场与操作分段 / 逐句台词 + 说话人 / 任务归属**，
并用画面字幕去**校验资产里的 actor**；换新录屏**不用改代码**。

| 项 | 内容 |
|---|---|
| 工具 | `tools/decompose_cutscene.py`（scan → shots → thumbs → band → subs → match → export） |
| 页面 | `export/cutscene/index.html`（播放器 + 时间轴 + 台词流 + 镜头墙 + 角色/覆盖/缺口，多段录屏可切换） |
| 数据 | `export/cutscene/dialogue.{json,csv}`、`shots.{json,csv}`、`summary.json` |
| 规则 | **`docs/任务与剧情/录屏反拆解规则.md`**（判据/阈值/反例/自检/换片怎么跑） |
| 中间产物 | `raw/cutscene/<视频名>/`（每条录屏独立，互不覆盖） |

**样本实测**（`录屏/带说话人录屏.mp4`，35:14，第一章）：

| 指标 | 值 |
|---|---|
| 镜头 / 过场镜头 | 149 / 114（过场 8 段，18.8 分钟） |
| 过场镜头中位 | 3.75 s（操作镜头 20.4 s） |
| 字幕行 | 261 |
| 匹配进剧本 | 227 句（剧本对白 192 + 音频库 35） |
| 任务归属 | WNT1 162 / WNT2 66（无杂任务） |
| 说话人 | 202 句已认出；18 句强证据中 **14 一致 / 4 冲突** |

**三条可迁移的判据**（详见规则手册）：

1. **过场必有上下黑边** → 按片高 2.5% 判，任何分辨率成立；
2. **硬切让相邻帧归一化互相关骤降到 <0.32，运镜不会**（骑马跟拍实测 gdiff 12.3 却 gNCC 0.875）——
   只用帧差会把运镜误判成切镜；
3. **画面字幕自带「名字：」**，是校验 `.ymt` actor 的独立证据；句尾的名字属于**下一句**。

**新录屏怎么跑**：

```bash
uv run python tools/decompose_cutscene.py --stage all --video "录屏/xxx.mp4"
# 多条：--video a.mp4 b.mp4   ／ 整个目录：--all-videos
```

字幕带位置、黑边高度、任务范围都自动探测（已在两条**未参与调参**的片段上验证：
`raw/capture/wnt1_320_400.mp4` 80 秒全流程跑通、18 句全部匹配进 WNT1）。

**已知缺口**：暗景相似构图会漏检 2~3 个切点/30 秒（已用 `cut_conf` 标注）；分支配音台词不会出现在单次录屏里（正常）。

> **过场解析的最终结论**（2026-10-23）：`.yad` 里存的是**未剪辑的 take 素材**，
> 分页时长求和大过场总长（`wnt1_mcs2` 85.7 s vs 38.8 s）、资产侧节奏中位 6.43 s vs 录屏实测 3.75 s，
> 都指向同一件事：**裁剪点与选版在 `.yas` 时间轴 / 运行时**，`/.ycd/.yad` 拿不到。
> 能确定的是「哪些过场、几镜、谁在场、总时长、素材长度、官方播放顺序」；不能确定「第 N 镜精确秒数」。

**说话人（2026-10-23 专项结论）**：RDR2 的本地化文本库 `<id>aud.yldb` **没有逐句说话人字段**——
每条形如 `hash | 0 | node_ptr`，node 里只有「字符串指针 + 字节长度」，没有 actor/voice 引用；
人物语音是**按角色分包**的 `.awc`（`x64/audio/sfx/PEDS_*.rpf`，8038 个名字在 names.txt 里），
演出编排在 `anim/animscenes/script@story.rpf`（**2 281 个 `.yas`，已提取到 `raw/story/animscenes/`**），
但 `.yas` 是 PSIN 二进制（只可见 chunk 标签，角色/台词是编码值）⇒ **要 100% 说话人，必须解 PSIN 或运行时 hook**。

- `export/story/speakers.json`：每段对话的**参与角色** + 逐句 `who`。
  - `conf=high`：玩家对话选项（确定）；
  - `conf=infer`：**称呼锚点**——某句里出现“迈卡？”这种呼唤，说明这句是玩家说的，可反推对手是谁（准确率最高，669 句）；
  - `conf=low`：没有锚点时按轮次交替推（3 815 句，可能错）；
  - 合计覆盖 **4 508 / 22 802 句（20%）**；查看器默认显示，`low` 带“（轮次推测）”后缀，可在页头勾选关掉。

  把截图放进 `raw/capture/shots/<对话组>_1.png`，会自动贴在标注页对应段落上方当参考（**截图只能当参考图，不能替代录音**）。

## 6. 本次会话修掉的关键问题（血泪记录）

| 问题 | 根因 | 修法 |
|---|---|---|
| 铁轨**整条消失** | 铁路资产名带 `_r_c_`、包围盒又扁又宽，被"地表贴片"和"又扁又大"两条剔除规则同时命中 | `tools/add_rail_network.py` 用 joaat 反查哈希找回 1,359 个铁路对象并贴地 |

| 房子**埋半截** | 模型原点多在底部之上（局部 minz 中位 −2.4 m，p10 −15.8 m） | 落点 = `e.z − bbox_minz × scale_z` |
| 坡地城镇被压平 | 地台用了单一标高 | 改为「平滑高程修正」，保留坡度 |
| 城内地面**是草色** | 地形 UV 的 V 轴反了（PNG 行 0 = 北，Blender v=0 在图底） | V 用 `(y−Y0)/W` |

## 9. 骑砍2 mod 包体预算（实测）

| 方案 | 几何 | 贴图 | 地形 | 合计 |
|---|---|---|---|---|
| 全量直转（float32 + 512 BC7） | 4.4 G | 2.1 G | 0.09 G | 6.6 G |
| **16bit 量化 + 512 BC7** | 1.9 G | 2.1 G | 0.09 G | **4.1 G** |
| 16bit + 256 BC7 | 1.9 G | 0.5 G | 0.09 G | 2.5 G |
| 只做 43 镇建筑 | 0.8 G | 0.2 G | 0.09 G | **≈1.1 G** |

50 GB 只会发生在「每个场景各存一份几何」的错误做法下。正确结构：**prefab 库全局去重 + 场景只存引用 + 每块 2 MB heightmap**。
