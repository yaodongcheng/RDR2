1. **对象名 hash 丢前导零**（`e_9862dfc`）→ 旧代码按 8 位截取，**5,864 个对象从未被识别**

### 为什么原来的 `sdn.blend` 没有桥和铁轨（结论）

1. `export_sdn_gltf.py` **圆形硬裁 r=620 m**（圆心 2555,−1151）。桥距中心 **750~1113 m** ⇒ 整座桥在圆外；
   半径 620 是 `build_settlement_previews.py:86` 给 sdn 的硬编码。
2. **模型库没抽铁路**：`work/sdn/models` 里 `_r_c_`/`_r_b_` = 0 个 ⇒ 圆内那 150 个铁路实例虽然通过半径检查，
   但 hash 匹配不到模型文件，被静默跳过。

### 修复步骤（可复现）

```bash
# ① 抽铁路模型（levels_1 是桥/栈桥，levels_2 是轨面）
rdr2rpf extract ".../levels_1.rpf" out "area/nopq_11_14/nopq_11_14_rails_"      # 得 rpf
rdr2rpf extract out/.../nopq_11_14_rails_a.rpf out/rb_a "" --recurse           # 得 n_1114_r_b_*
rdr2rpf extract ".../levels_2.rpf" out "area/rails/nopq_11_14_rails_c"          # 得 rpf
rdr2rpf extract out/.../nopq_11_14_rails_c.rpf out/c114 "" --recurse           # 得 n_1114_r_c_*
cp -n out/rb_a/*.ydr out/rb_b/*.ydr out/c114/*.ydr work/sdn/models/

# ② 放大半径重导
uv run --with pillow python tools/export_sdn_gltf.py --cx 2555 --cy -1151 --r 1250 \
    --ydr work/sdn/models --chunk 160 --maxs 512 --out export/levels/world/gltf/sdn_full

# ③ 装配（地形范围要跟着放大）
blender -b -P tools/blender_assemble_sdn.py -- \
    --gltf ".../sdn_full/tiles/*.gltf" --out deliverable/blender/sdn_full/sdn_full.blend \
    --no-props --no-int --area "1300,-2400,3810,100" --shots ""
```

## 八、三个 blend 到底什么关系（2026-10-27 审计）

### 结论：**完全不等价，是三条不同的管线**

| 维度 | `continent.blend` | `sdn.blend`（10-19 旧） | `sdn_full2.blend`（本轮） |
|---|---|---|---|
| 做法 | ymap → **按 tile 烘焙成整块网格** | gltf **单件** | gltf **单件** |
| 范围 | 全图 12.3 km | 圆 r=**620** | 圆 r=**2000** |
| 铁路 | `RAILCELLS` 1,359 + `rail` 2,222（烘焙块） | **0** | **379** |
| 桥 | 烘在 tile 块里，**库中无独立件** | 4 件（城区北 `new_gar_03_bridgeb`，非跨水桥） | **353 件**（钢桁架 + 栈桥） |
| 模型库 | `assets/lib_native` 54,893（实测 `bridge`/`_bri`/`tres`/`truss`/`rail` **全部 = 0**） | `work/sdn/models` 2,733 | `work/sdn/models` 3,309 |
| 陷地处理 | ✅ `pad_field()` | ❌ | ✅ 本轮补做 |
| 四元数共轭 | ✅ 显式 `(w,-x,-y,-z)` | gltf 已烘焙 | gltf 已烘焙 |

**为什么在 continent 里「看得到桥、但铁轨断」**：continent 的铁路是 tile 烘焙网格（桥和轨道烘在同一块里），
所以局部能看见桥；但**独立桥件（bri/tres）在 `lib_native` 里一个都没有**，一旦某个 tile 块被剔/缺失，
没有件可以补，就表现为"铁轨断了"。

**为什么 `sdn.blend` 没这座桥**：① 圆 r=620 把桥（距中心 750~1113 m）整段裁掉；② `work/sdn/models` 里
铁路模型 0 个。

## 十一、地形问题的最终结论（2026-10-28）—— 不要拟合，用原生

### 结论

**RDR2 的地形和建筑高程都是原生准确的，不需要任何拟合。**

| 数据 | 来源 | 精度 |
|---|---|---|
| 地形 | `work/terrain/H4.npy` | 3075×3075，**4.00 m/px**，由 30,697 个地形 patch 解析而来 |
| 建筑 | ymap 实例自带 `z`（`e[3]`） | 米级原值 |

> 地形精度补充：RDR2 的地形 patch 规格是 **64 m × 64 m、17×17 顶点**（`tools/build_terrain_heightmap.py` 注释），
> 64/16 = **4 m 一个顶点**，这是引擎的固定规格。游戏里看着更细腻，靠的是**法线贴图 + GPU tessellation + 细节纹理**，
> 不是几何更密。

### 谁破坏了它

`blender_continent.py` 的 `pad_field()`：把城区 100 m 格内的地形压平到"所有实例 z 的中位数"，
实测中位 **−1.12 m**、压低 >0.5 m 的格子占 **63.9%**，于是建筑整片浮空。
后续为了修浮空写 `fit_terrain_sdn.py` 拟合抬回，又顶穿公园地面件（park_terrain 底 44.40 vs 地形 45.83），
画面支离破碎 —— **全是自造问题的连锁反应**。

### 正确做法（已执行）

`sdn_full2` **重装配**即可恢复（`blender_assemble_sdn.py` 的 `add_terrain` 直接读 H4 原生）：

| | 拟合后（坏） | 重装配后（好） |
|---|---|---|
| 公园地形 z | 45.83 ~ 46.33 | **44.62** |
| 与地面件底(44.40) 关系 | 地形顶穿 1.4~1.9 m | 地形在件下方，草坪完整 |

验收图 `work/verify/park_fixed.png`：草坪、园路、喷泉完整，与 `sdn.blend` 观感一致。

### 已废弃

- **`tools/fit_terrain_sdn.py`** ⛔ 头部已加废弃警告，默认拒绝执行（需 `--i-know-what-im-doing` 才跑）。
- **`blender_continent.py --no-pad`** 应作为默认：`continent_v3.blend`（8.67 GB，PAD 0 次）就是原生数据版。

### 待办（可选，不是必须）

1. H4 有 **26.7% 空洞**（2,527,046 格无数据），表现为一片片平"假地面" —— 补 patch 可改善。
2. 想让地形更像游戏，方向是**给地形加法线贴图 / 细节纹理**，不是加密网格。
