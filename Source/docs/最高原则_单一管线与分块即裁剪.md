# 最高原则：单一管线 · 分块即裁剪

> 2026-10-27 由用户确立，**优先级高于本项目所有其他文档与约定**。
> 任何新工作开始前，先读这一页；与本页冲突的做法一律作废。

---

## 一、原则原文（不得改写）

1. **只有一个全集**：`continent.blend` 是**不含瓜玛岛的全集**。
2. **一切都只是裁剪**：夏洛蒂的家、圣丹尼斯、以及将来任何区域，都只是从这个全集里**按坐标范围裁出来的子集**，**不是独立零件**。
3. **严格等价**：给定同一个坐标范围，**从全集裁出来的区域，必须与"该区域的独立产物"逐对象、逐变换、逐地形一致**。
4. **一套方法**：验证一个区域后，方法直接推广到别的区域。**不允许为每个区域重新造轮子、重写一套管线。**

---

## 二、由此推出的硬性约束

| # | 约束 | 违反的表现 |
|---|---|---|
| 1 | 全项目只有**一条构建管线**：`tools/blender_continent.py`（ymap → blend） | 出现第二条装配脚本 = 两套结果，天然不等价 |
| 2 | 区域产物必须由**全集裁剪**得到（`tools/crop_blend.py --bbox`），不得重新构建 | 同一坐标范围两边对象数/高度/朝向对不上 |
| 3 | 全集有的能力（地形贴合、四元数共轭、分类、铁路豁免、陷地修复）**裁剪后必须原样保留** | 子集贴地率 24% vs 全集 47% |
| 4 | 区域里的**新增修复**（如抬轨道）必须先做进全集管线，再靠裁剪下沉到各区域 | 只修子集，换个区域又重犯 |
| 5 | glTF / 网页预览**只是查看器**，不产出交付场景 | 用 gltf 装配出 blend 当交付物 |

| 产物 | 走的管线 | 与原则的关系 | 处置 |
|---|---|---|---|

| `willard_full.blend` | `merge_interior_into_willard.py`（MLO 合并） | ⚠️ 局部特例，但也应改为"全集裁剪 + 室内合并" | 待并入 |

**已知的三处后果**（均由违反原则直接导致）：

1. `continent.blend` 的 `assets/lib_native`（54,893 模型）里 `bridge / _bri / tres / truss / rail` **全部为 0**，铁路只能靠 tile 烘焙网格，块缺失就补不回来 ⇒ "看得到桥、但铁轨断"。
2. `sdn.blend` 因 r=620 裁掉桥、且模型库无铁路 ⇒ "没这个桥"。
3. `sdn_full2` 的 `fit_terrain_to_buildings.py` **写死 `ENTITIES` 集合**，换个产物直接 `AttributeError` ⇒ 经验无法复用（这正是"重复造轮子"的根源）。

## 四、收敛路径（按顺序做，不要跳）

1. **统一模型库**：把 `n_1114_r_b_* / n_1114_r_c_* / n_1114_r_a_*`（铁路、桥、栈桥）补进 `assets/lib_native`，
   并在 `blender_continent.py` 里确保 `--rails` 覆盖它们。
2. **统一修复能力入口**：把 `fit_terrain_sdn.py`、`fix_rail_sink.py` 的能力**合并进** `blender_continent.py` 的后处理链
   （`pad_field` → `fit_terrain` → `rail_lift`），任何产物（全集或子集）都跑同一套。
3. **新增 `tools/crop_blend.py`**：从 `continent.blend` 按 bbox 复制并删除范围外对象，
   保证"裁剪 == 子集"，并输出裁剪报告（对象数 / 各分类计数 / bbox / 地形哈希）。
4. **等价性回归**：同一 bbox（圣丹尼斯 `x[1300,3160] y[-1910,-510]`）分别产出
   "全集裁剪"与"历史独立产物"，逐项比对；差值必须为 0 才允许宣布该区域完成。
5. 历史产物（`sdn*.blend`）保留但不作为基准，避免继续分叉。

## 五、验收口径（任何区域通用）

对区域 R（bbox 给定）：

| 检查项 | 通过标准 |
|---|---|
| 对象集合 | 全集 ∩ R 的对象名集合 == 裁剪产物对象名集合（**差集为空**） |
| 变换 | 每个对象 `matrix_world` 最大分量差 < 1e-4 |
| 地形 | 同网格点数、逐顶点 z 最大差 < 1e-3 |
| 分类计数 | 13 类 × 地块计数完全一致（2026-10-29 起；`lod`/`terrain_cell` 为新增两类） |
| 贴地率 | 与全集同一算法、同一数值（不允许子集另算一套） |
| 铁路/桥 | 实例数、模型名、位置与全集一致 |

**任一项不通过 = 该区域未完成，不允许用"新方法"绕过。**

## 六、绝对禁止的「擅自改动」（2026-10-28 补充）

> 这一节是**历史错误清单**，每一条都真实发生过，代价是整片城区消失或发黑。
> **任何人（包括 AI）都不得以"看起来像冗余""可能是贴片""大概率是这张图"为理由，自行删改数据。**

### 6.1 禁止擅自剔除网格体

**错误**：`blender_continent.py` 里曾有三条剔除规则，共丢掉 **31,533 个实体**：

```python
TERRAIN_CELL = r'(_r_c_\d+|_rc_\d+|_ground\d*$|_terrain)'
cell      = (abs(dx-64)<2 and abs(dy-64)<2) or (abs(dx-128)<2 and abs(dy-128)<2)
flat_wide = (dz < 2.0 and max(dx,dy) >= 16) or max(dx,dy) > 45
```

其中 `max(dx,dy) > 45` **不看高度**，把 45.4 m 高的火车站本体、65.8 m 长的外墙当成"扁平贴片"扔了，
场景里只剩 `_glue` 拼接件 → 满屏镂空建筑。

**规定**：
- **所有能加载的网格体一律保留**，不允许按尺寸/名字/地形重合度自行剔除。
- 唯一允许的"不显示"：**植被**（默认隐藏，不删除）。
- 地形高度块（`*__hd_0_*` 地图内 64 m 小块 / `out_<字母>_<行>_hd_<列>` / `outg_…` 两套地图内外围 1024 m 大块）
  等**与高度图重复**的件，也**只隐藏、不删除**（归入「地形块」类，整类默认隐藏；2026-10-29 起不再搬进 `HIDDEN_*` 垃圾桶）。
  2026-10-30 用户裁定保持此口径（**文件里保留、默认不显示**）：`out_*` 85 个 + `outg_*` 71 个原先漏判成 `unknown` 而可见，
  已在 `classify_entities.py` 的 `terrain_cell` 规则里补齐三族。
- **地下 / 停放件**（`*_tempbox*`、`q_11_damn`，以及任何**完全埋在地表之下 ≥10 m** 的物件）同样**只隐藏、不删除**：
  归「地下停放」类，整类默认隐藏（2026-10-30 用户裁定）。
  **判据（用户口径，考虑地形不是平面）**：在对象占地范围取 9 点读地形高度，取**最低**那个；
  若「最低地形 − 对象最高点 > 10 m」→ 地下。**对象最高点只要高过地表（露出地面）就一律不算**。
  另加两条：`tag=parked_offmap` 直接归此类；「地形块 / 远景 / 水面块」不参与（各自有类）。
  ⚠️ 旧的两条（`|x|<1 且 |y|<1` 原点、`z < −80` 绝对地板）已废弃 —— 地形最低点才 −79.7 m，绝对 z 判不出"地下多深"。
- **水面块**（`a_water_*`，含瀑布/冰面共 341 个）与**占位代理**（`*_proxy*`、`*_occ_*`、`*placeholder*`、
  `*donotdelete*`、`amb_pun_*` 等）也各归一类、整类默认隐藏 —— 前者与我们的单水面（z=40.5）同高打架，
  后者是游戏不渲染的音频/遮挡/阴影代理盒（2026-10-30 用户裁定）。
- 代码里不允许出现"因为看起来多余所以 continue"的分支。

### 6.2 禁止擅自修改地形高度

**错误**：`pad_field()` 把城区地形压到"100 m 格内所有实例 z 的中位数"，实测中位 **−1.12 m**、
压低 >0.5 m 的格子占 **63.9%** → 建筑整片浮空。之后又写 `fit_terrain_sdn.py` 去拟合抬回，
结果把公园地面件顶穿 1.4~1.9 m，画面支离破碎。

**规定**：
- 地形**只用 RDR2 原生高度**（`work/terrain/H4.npy`，4 m/px），不做压平、不做拟合、不做局部拉伸。
- 建筑 z 用 **ymap 原值**，不许为了"贴合"去移动建筑。
- `pad`、`fit_terrain`、`clamp`、`carve` 这类脚本**默认不得出现在构建链里**。
- 需要地形特殊处理时，必须先说明理由并获得明确同意。

### 6.3 禁止靠猜测匹配贴图

**错误**：`export_sdn_gltf.py` 的 `TexLib.get()` 在精确名找不到时，会按"词元相似度"猜一张贴图：

```python
toks = [w for w in re.split(r'[^a-z0-9]+', base) if len(w) >= 4]
for k in self._alb:
    hit = sum(1 for w in toks if w in k)
    if hit >= max(2, len(toks)-1):  best = ...
```

结果 `new_gar06_park_terrain`（公园地面）被配成 `bra_dr_burn_01`（**烧焦地面**）→ 一片黑。

**规定**：
- 贴图只走两级**精确**匹配：① 模型自带 `+hidr.ytd` 里的同名贴图 → ② 全局贴图库的精确名。
- **禁止 fuzzy / 前缀猜 / 词元猜**。找不到就留空，用中性兜底色，并计入"缺贴图"统计。
- 入库后必须能回答"这张贴图来自哪个模型/哪个 ytd"，不允许来路不明。

### 6.4 禁止丢失可读信息

**错误**：对象名曾用 `'e_%s' % hex(hash)[2:10]` —— `hex()` 不补零，
`0x0777d697` 变成 `e_777d697`，且只有 hash 没有原名，导致：
- 用户搜不到 `new_pie_train_43_2`
- 分类脚本按错 hash 反查 → 未分类 3,555 个

**规定**：
- 对象名**必须用 RDR2 原资产名**（`new_pie_train_43_2`），hash 存进自定义属性 `obj["hash"]`。
- 任何 hash → 字符串的转换必须 `'0x%08x'` 补零。

> **2026-10-29 复发（同一类错误，换了个位置）**：`dump_model_lib.write_model()` 用 `hex(h)`
> 生成 `.mdl` 文件名和 `index.json` 的键 → 库里同时存在 `0x4ac59bc` 与 `0x04ac59bc` 两种键
> （**3,430 个**）。多数只是重复，但有 **367 个模型只有不补零的键**，构建时按 `'0x%08x'` 查表查不到，
> 于是"库里有模型、场景里却没有"，还被算进"缺模型"。
> 修法：`tools/normalize_lib_index.py`（以磁盘 `.mdl` 为准重建 index）+ `write_model` 改补零。
> **判据**：任何"写到磁盘/写进 JSON 的 hash 字符串"，都必须能过 `re.fullmatch('0x[0-9a-f]{8}')`。

> **2026-10-29 复发之二（贴图侧，代价更大）**：`.mdl` 子网格**只存 tid、不存贴图名**，
> 而 `dump_model_lib` 被重跑过、`tex` 表被更小的池覆盖过 —— 结果：
>
> | 实测 | 数 |
> |---|---|
> | `assets/lib_native/tex/` 里的 PNG | **7,074** |
> | `index.json` 的 `tex` 表 | **5,292**（id 0..5291） |
> | 孤儿（磁盘有、表里没登记） | **1,782**（id 5292..7073） |
> | 引用越界 tid 的子网格 | 71,951 / 221,494（**32.5%**） |
> | 因此"一张 albedo 都没有"的模型 | **20,858 个 / 场景 23,099 个实例** |
>
> 修法（找回，不是猜）：`tools/register_orphan_textures.py` 把孤儿按 **id** 补登记
> （文件名就是 tid，与 `.mdl` 同一代池；抽样像素比对 **5/5 一致**），名字用 `tex<id>` 并打 `x:1` 标记；
> 然后 `postprocess_continent.py --relink` 重挂材质。
> **根治方向（未做）**：`.mdl` 的子网格记录里加**贴图名字段**，从此不再依赖 id。
>
> **2026-10-29 复发之三（id 复用导致 name↔file 错位）**：`tex` 表被多次重建/排序、`tid` 还被复用，
> 于是"表里写的名字"和"`tex/<id>.png` 里的图"可能不是一个东西。实测：
> `new_gar06_park_terrain` 的 `s` 是 `[353,352,352,352]`，表里 352 叫 `p_doornbd39x_ab`，
> 而 `tex/0352.png` 逐像素（diff **0.0**）就是 `nbx_ground_dirt04_ab`；
> 另抽 300 条核对，可比对 83 条里 82 一致 / 1 不一致。
> **结论**：贴图名只能当线索；**不要用"表里的名字"倒推贴图内容**（§6.3 禁猜）。
> 根治同前：id 改成名字 hash（不可变）+ `.mdl` 存名字。详见 `docs/TODO.md` §0.6 #3。

### 6.5 禁止伪造环境数据

**错误**：水面曾用 2048² 采样生成 **285,550 个四边形**（57 万三角面）+ 半透明材质，
水位是重建的 **42.75**（真值 40.5），既卡又淹桥墩。

**规定**：
- 环境要素（水面、照明）优先用**游戏真值**（`water.xml` 的 z=40.5）。
- 无法获取真值时，用**最简几何**表示（单平面），并在文档标注"非真值"。
- 不允许用大规模重建网格去"模拟"环境元素。

### 6.6 禁止把 LOD 合并块当"缺口"去补、更不能硬装

**错误（差一点犯）**：2026-10-26~28 的文档把 **49,778 种 / 50,007 个实例**叫「未命名 archetype 缺口」，
并把它列为"最高优先级：补全模型库"。2026-10-29 复核证明：其中 **46,536 个实例是 LOD 合并块**——

- 定义它们的 ytyp **全部**叫 `*_lod_combine_metadata*`（88,626 / 96,141 条 archetype）；
- 每条的 `name` 与 `assetName` **完全相同**（96,141 条里 0 条不同），没有第二个名字；
- bbox 中位 **64 m**、P90 **128 m**，是整块瓦片而不是零件；
- 77.5% 的实例水平 0.5 m 内就盖着已装好的具名件；
- 全量 RPF 索引（4,021 个包 / 74,449 条 drawable）里**找不到它们的条目** ——
  游戏在运行时按子 archetype 现场合并这一层远景 LOD。

**规定**：
- **LOD 合并块不进 `ENTITIES`**，也不计入"缺模型"缺口的验收数字；统计里单列 `lod_block`
  （`tools/audit_missing_models.py`）。
- **禁止**为了把数字做漂亮，把这类块塞进场景或直接删除：前者会盖住 HD 几何，后者违反 §6.1。
- 判断"缺的是不是真件"，必须先跑 `audit_missing_models.py` 出桶，再看 `real_ytyp` / `no_definition`。
- 同理：**"能不能从包里抽回来"要先建 RPF 全量索引**（`tools/rpf_index.py`），不许凭"包里有 8 个 levels"猜。
