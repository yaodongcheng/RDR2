## 二、还原方法（每一步都可核对）

### 1. 对话：脚本里的组标签 → 字幕库的逐句中文

RDR2 脚本里播放对话是这么写的：

```c
func_xxx("RBRAN_LASSO1");          // 触发一个对话组
```

字幕库 `<任务>aud.yldb` 里按 **组名 + 序号** 存：

```
RBRAN_LASSO1_1 = "离我爸爸远点！"
RBRAN_LASSO1_2 = "算了，比利！"
```

所以还原逻辑是：**扫脚本里所有大写标签 → 拿这个任务自己的字幕库挨个查 `标签_1…N`**。
不做前缀过滤（实测命名不统一：`RABI22→RABI22_*`、`RODDF1→RODDF_*/RODF1_*`、`RCKPT1→CKPT3_*/CKPTB_*`），
因为字幕库本身是该任务专属的，查得到就是它的。

> 这一步产出了 27 个任务、1 398 句**原文台词**，不含任何改写。

### 2. 流程：按源码行号排时间轴

脚本里每类调用都抽出来，按行号排序 = 游戏实际执行的先后：

| 事件 | 来源 | 例 |
|---|---|---|
| 对话 | 对话组标签 | `RBRAN_LASSO1` |
| 生成 | `PED::CREATE_PED` 等 | `CREATE_PED ×3 · PROP_CORPSE…` |
| 行为 | `TASK::TASK_*` | `TASK_CARRIABLE`（扛人） |
| 演出 | `ANIMSCENE::_CREATE_ANIM_SCENE` | 脚本动画场景 |

每条都带 `L<行号>`，点一下复制 `脚本:行号`，可以直接去
`raw/script_full/1491.50/<脚本>` 核对。

> 去掉了纯状态类行为（`TASK_CLEAR_LOOK_AT`、`TASK_STAND_STILL` 等），
> 它们会让时间轴只剩噪音，且不构成"这一步在干什么"。

### 3. 脚本对齐：内容验证，不靠猜

`mission_scripts.json` 只覆盖 194 个任务，150 个随机任务里 61 个没映射上。
`tools/recover_mission_scripts.py` 补 16 个，规则是**三条同时满足**：

1. 脚本名去掉 `rcm_/bh_/bounty_` 前缀后，以任务 id 的数字后缀结尾；
2. 脚本名包含任务 id 字母部分（去掉开头 R）的前 3 位；
3. **脚本内容里出现 `<ID>_` 或 `<去R前缀>_` 的标签**。

第 3 条是关键：早期版本只看"数字相同"，把 `CONSUMABLE_MEAL_CAMP_STEW_DAILY_1`
配到了 `cv_cc_am_cnf_01.c` —— 那是造假，已废弃。现在补回来的都对得上：

```
RCAL12 枪手传：第3部分   -> rcm_callaway12.c
RCKPT3 一个聪明好动的男孩：第3部分 -> rcm_crackpot3.c
RGUN11 埃米特·格兰杰    -> rcm_gunslinger1_1.c
RMARY1 真爱易逝：第1部分  -> rcm_mary31.c
RMUD31 火上浇油：第1部分  -> rcm_mudtown3_1.c
```

## 三、一个例子：RBRAN「马克·约翰逊」（赏金 $25）

界面里长这样（全部来自源码，无一句是我写的）：

```
描述   数次逃脱制裁的马克·约翰逊因抢劫火车和驿站马车而被通缉，要求活捉。罗兹提供赏金 $25。
失败   孩子被吓坏了。 / 马克·约翰逊死了。 / 马克·约翰逊逃走了。

阶段 1 · func_36  L1814
  RBRAN_EMBRACE1 (5 句)   "别哭，我们为你感到骄傲，孩子。"
  RBRAN_LASSO1   (2 句)   "离我爸爸远点！" / "算了，比利！"
  RBRAN_LASSO2   (2 句)   "不要伤害他，先生。" / "你一定要在孩子面前这么做吗？"
阶段 2 · func_96  L3096   行为：搬运/扛人（TASK_CARRIABLE）
阶段 3 · func_107 L3472   BRA_HOGWAK  "该死。我的头。" / "你不必那么过分。"
```

这段能看出任务真实的样子：**当着孩子的面把人绑走**，孩子吓坏就是失败条件。
这不是我设计的，是这个任务的原文和原逻辑。

## 四、还还原不了的（诚实列出）

| 缺什么 | 为什么 | 现在的处理 |
|---|---|---|
| **触发条件**（在哪个坐标、什么时段、什么前提下触发） | 目标/触发走的是运行时全局数组，脚本里没有常量 | 不显示 |
| **演员初始站位** | 同上，且过场资产里没有独立场景文件 | 不显示 |
| **镜头与成片剪辑** | 需要逐镜解 `.ycd/.yad`，且没有镜序 | 不显示 |
| **大部分任务的目标文案** | UILOG 目标 key 由 `func_262()` 从 `Global_1347702[i].f_3` 取，是运行时字符串 | 界面写明"未解出，不编造" |
| **45 个任务的脚本** | 文件名与 id 对不上、内容里也没有该 id 的标签 | 列入缺失清单 |

> 这些都是**解包层面的硬缺口**，不是我偷懒少做了。
> 要补，得先解出"任务 id ↔ 脚本/触发"的调度表，或拿到对应 `.rpf` 的路径。

## 六、和之前那版"试玩台"的区别

| | 之前（已删除） | 现在 |
|---|---|---|
| 数值 | 成功率、荣誉、赶路距离都是编的 | **一个数值都没有** |
| 内容 | 拿真任务当卡牌，套一层自创玩法 | 按源码行号还原真实执行内容 |
| 台词 | 用上了，但被塞进自创对话流程 | 按脚本里的**对话组**归属，顺序即触发顺序 |
| 可核对性 | 无法核对 | 每条带 `脚本:行号` |
| 缺失部分 | 藏起来 | 单列「缺失清单」 |
