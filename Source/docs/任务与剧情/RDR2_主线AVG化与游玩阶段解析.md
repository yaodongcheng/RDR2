# 主线任务的「观看阶段 / 游玩阶段」拆分与 AVG 化

> 回答两件事：
> 1. 主线任务能不能拆成「玩家观看」和「实际游玩」两段？——**能，而且有源码级证据**。
> 2. 游玩段到底「去哪里、找谁说话、打谁」解出来没有？——**目标层解了（611 条原文目标 + 787 张步骤卡），触发层没解（仍然是运行时）**。
>
> 生成脚本：`tools/build_avg_main.py`（数据）、`tools/build_avg_bg.py` + `tools/audit_avg_bg.py`（背景）、
> `tools/build_avg_portraits.py`（立绘）。
> 数据：`export/levels/world/avg_main.json` + `export/avg/data/`。
> 页面：`export/avg/index.html`（AVG 播放器）、`export/avg/playbook.html`（游玩手册）。

## 0. 一句话结论

RDR2 每个主线脚本里都有一张**过场段链**，它直接告诉了你「哪一段是过场、哪一段是纯游玩」：

```c
func_784(uParam0, iLocal_81, iLocal_82, 116734, 116743, 116913, 117093, 117139,
         "WNT1_INT_WAGON", 2, -1);                     ← 过场：开场马车
func_784(uParam0, iLocal_84, iLocal_85, 119870, 119879, 120161, 120378, 120772,
         "", 0, -1);                                    ← 空名字 = 纯游玩段
```

签名是 `(参数块, 状态from, 状态to, mark1..mark5, "过场名或 0", flag, clip数)`。

- **过场名非空** → 这一段播过场，就是玩家「只看不操作」的观看阶段；
- **过场名为空** → 这一段没有任何过场，就是玩家真的跑图、说话、开枪的游玩阶段；
- `mark1..mark5` 与 `story/cutscene/mission_timeline.json` 里的 `marks` **逐值相同**，
  所以能反查这段过场的**时长 / 镜头数 / 累计起点**。

这条链是本项目里**第一次**把「观看 / 游玩」按游戏自己的写法分开，而不是靠猜。

## 2. 观看阶段的 AVG 怎么搭

### 2.1 为什么用 AVG

过场本身是**引擎实时演出**，要按原样复刻就必须还原：每镜相机轨迹、演员走位、道具、动画剪辑。
项目里已经确认拿不到的部分：

- 过场相机数据只有**局部坐标**（如 `pos=[24.71,-7.72]`），没有世界变换 → 没法直接放进世界场景；
- `.ycd` 没有坐标、`.yad` 原地表演根位移仅 ±0.02~0.05 m；
- 逐镜成片时长 / 镜序也只有部分解出（`mission_timeline` 有 304 段）。

所以用 2D 背景 + 立绘的 AVG 把这个阶段**换一种表现形式**，是绕开这些缺口的正确做法，
而不是硬做一条半真的 3D 过场。

### 2.2 背景不是按台词走的（常见疑问先答）

**台词本身不带坐标。** 每一句只有 `序号 / 说话人 / 中文`，没有任何位置字段。
背景的选择链是「**任务 → 地点 → 机位**」，和台词无关：

```
mission_coords.json  primary(cluster 中心 x,y,z + radius)      # 脚本里 211 个坐标点聚类
        ↓ 最近邻
settlements.json     最近据点 code（adl / val / sdn …）
        ↓ 一个据点渲 2 个方位角
export/avg/bg/<code>_<0|2>.jpg
        ↓ hash(任务id : 据点 : 段号) % 2
该段用哪一张
```

所以同一个任务的**所有过场段共用同一个地点的背景**（只换机位），
换任务才换地点 —— 因为「第 3 章发生在谢迪贝莱」这件事是任务级信息，不是台词级信息。

背景图本身是**真实 3D 场景的离线渲染**：

| 层 | 来源 |
|---|---|
| 建筑/道具 | `export/previews/<code>/tiles/*.gltf`（解包后装配的真实模型，如瓦伦丁 807 实例 / 356 模型） |
| 地面 | `export/world/world_color_4096.png`（全图地面彩图，3 m/px）贴在**一块平面**上 |
| 机位 | 我在 `previews/index.html` 加的固定取景参数 `?shot=N&k=0.50&h=0.17&fov=45`（N = 方位角） |
| 出图 | headless Chrome（`tools/bgshot.mjs`）截图 1600×900 JPEG q90 |

> **画面里那股"地图感"来自地面**：地面是平面 + 全图彩图贴图，不是解包出来的地形网格。
> 建筑是真的、位置是真的，但脚下那片地没有起伏也没有细节材质。
> 要彻底解决得用 `deliverable/blender/continent.blend`（真地形 + 7 层材质）重渲，属于下一轮。
>
> 页面上每段都有一行小字写明出处：`背景：真实场景渲染 · 犁刀村 · 机位 2/2（阿德勒牧场 未烘出建筑，改用此场景）`。

### 2.3 三层素材都不靠画

| 层 | 来源 | 做法 |
|---|---|---|
| **台词 + 说话人** | 任务音频库 `<mid>aud.yldb`（键 `<过场名>_<序号>`）+ `conversation_actors.json`（每行 actor）+ `speaker_overrides.json`（actor→中文名） | 逐句取出，98.9% 有实名 |
| **2D 背景** | 见 §2.2：真实场景 glTF + 固定机位离线渲染 | 1600×900 JPG，一地点 2 个方位角 |
| **立绘** | `export/npc/cs/cs_*.glb`、`player_zero.glb` | Blender Cycles 渲半身像（透明底 700×920，85 mm 长焦、三点光） |

### 2.4 播放器行为

`export/avg/index.html`：

1. 任务 → 拍平成一条 beat 序列：`开场卡 → [过场段卡 → 逐句台词] → 游玩段卡 → … → 收尾`；
2. 过场段：换背景（带 0.5 s 交叉淡化）→ 立绘进场（当前说话人亮、次要人物压暗）→ 打字机逐字；
3. **碰到游玩段就停下**，弹「游玩阶段卡」：列出这一段的目标（去哪里 / 找谁 / 打谁 / 坐标 / 区域）+ 失败条件，
   玩家点「继续观看」才回到 AVG；
4. 键盘：空格/回车继续，← 上一句，A 自动，Esc 任务列表；
5. 深链 `?m=WNT1&at=110` 直接跳到某一段（写文档、验收、复现都用它）。

## 3. 游玩阶段的「去哪里 / 找谁 / 打谁」

### 3.1 解到什么程度

**已经解出来的（可直接用）**

| 问题 | 数据 | 覆盖 |
|---|---|---|
| 这一段要做什么 | 目标文案，**yldb 原文，未改写** | 611 条 / 88 个任务 |
| 去哪里 | `mission_coords.json` 的真实坐标聚类（脚本里 `func_*` 的 211 个坐标点解析）+ 最近据点 | 105 个任务的主活动区；100 张步骤卡带字面坐标 |
| 找谁说话 | 目标文案里的「与 X 交谈」+ cast 名匹配（全名/简称双匹配） | 29 条 talk 卡 |
| 打谁 | 「击退/杀死/消灭…」+ cast 名匹配 | 42 条 fight 卡，另有 29 条 protect（保护谁） |
| 失败条件 | yldb 原文（跟丢/离场/NPC 死亡/被惊动） | 443 条 |
| 金牌挑战 | `challenges_sp_missions.meta` | 105 个任务 / 308 条 |

动作分布（748 张步骤卡）：

| 动作 | 数量 | 含义 |
|---|---|---|
| other | 265 | 其余目标（安抚马、审问、调整等） |
| follow | 163 | 跟随 X |
| goto | 118 | 前往某地 |
| loot | 56 | 搜刮 / 搜查 |
| fight | 42 | 击退 / 杀死 |
| protect | 29 | 保护 / 掩护 |
| talk | 29 | 与 X 交谈 |
| interact | 24 | 靠近 / 使用 / 检查 |
| carry | 22 | 扛起 / 捆绑 / 套索 |

最常被点名的对象：达奇 56、查尔斯 32、莎迪 32、约翰 25、迈卡 16、哈维尔 13、何西阿 12、大叔 12。

**还没解出来的（明确标注，不编）**

| 缺口 | 现状 |
|---|---|
| 目标的**触发条件** | 目标文本索引是运行时变量（`func_1812(iLocal_1838)`），静态拿不到；所以「哪个体积触发哪条目标」解不出 |
| 目标的**严格时间顺序** | 37 个任务有 `mission_steps`（按目标函数首次调用行号排序，可信度较高）；其余只有 yldb 顺序，属于**推断** |
| **生成多少敌人 / 敌人在哪** | `CREATE_PED` 的调用点能数到，但坐标与数量在参数里，且大量走运行时表 |
| 随机任务的触发时间/坐标 | 走运行时全局数组，脚本里没有常量（README §6 已记） |

为了让这些不确定**可见**，每条任务都带 `basis`：

```json
"basis": { "segments": "script-chain", "objective_assign": "steps-order-proportional" }
```

- `segments: script-chain` = 段链来自脚本（76 个）
- `segments: fallback` = 没有段链，用 `cutscene_scenes` 兜底（29 个 `rcm_*`）
- `objective_assign: steps-order-proportional` = 目标按脚本步骤顺序分配到游玩段（36 个）
- `objective_assign: yldb-order-proportional` = 只有 yldb 顺序，按数量均分（51 个）
- `objective_assign: none` = 没有目标文案（18 个）

**页面会把 `basis` 显示出来**，不会把推断当成结论。

### 3.2 游玩手册页

`export/avg/playbook.html`：

- 左侧按阶段列出「观看段摘要（时长/镜头/句数/首句）」和「游玩段步骤卡」；
- 点任意步骤 → 右侧小地图**定位到该步骤的世界坐标**（底图 `world_color_4096.png`，
  按 `x = -7684 + u×14.5 ; y = 4100 − v×14.5` 换算），并画出任务主活动区半径；
- 没有字面坐标的步骤只标区域，从地图上能看出「发生在哪个据点附近」。

## 5. 已知问题与下一步

| 问题 | 说明 / 下一步 |
|---|---|
| 29 个 `rcm_*` 任务没有段链 | 它们脚本里就是单场过场 + 一段游玩，已用 `cutscene_scenes` 兜底；要更准需要读各自的 `_INT/_EXT` 定义 |
| 130 个过场段没有时长 | 对应脚本不在 `mission_timeline` 的 72 个包里；补 `cuts_*.rpf` 的 `.ycd` 解析即可 |
| 125 个过场段没有字幕 | 过场用**资产名**（如 `RCHNT1_INT`）、字幕却挂在别的键上；已加「任务名前缀替换」兜底，仍有一批是真的没对白（动作过场） |
| 6 个地点用替身背景 | `adl / wal / sod / wap / che / hso / lon / abe` 的预览包没烘出建筑（实例 < 80），改用同章节主场景，`bg.json` 里标 `proxy`，页面会写明 |
| 小屋场背景偏空 | 犁刀村、迈卡藏身处这类只有几间木屋的地点，zone 半径远大于建成区 → 镜头拉远后像"雪原上一小撮房子"；根因同下一条 |
| 地面是平面 | 预览页的地面 = 平面 + 全图彩图贴图，没有地形起伏；用 `continent.blend` 重渲可解决 |
| 目标分配到游玩段是**按数量均分** | 真正的一对一映射取决于运行时索引，静态拿不到；有 `mission_steps` 的任务已按脚本步骤顺序分 |
| 立绘是 A-pose 半身像 | 来自 `cs_*` 静态模型，没有表情与动作；后续可做表情差分（同一模型换脸/换角度） |
