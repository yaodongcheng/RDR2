# 录屏反拆解规则手册

> 目的：**从任意一段 RDR2 主线录屏，反推出「镜头 / 过场 / 台词 / 说话人 / 任务归属」**，并且**换一条没见过的录屏也不用改代码**。
> 本文不是"某条视频的解析记录"，而是从样本里抽出来的**可复用规则**：每条都写清判据、阈值、反例和失效条件。
> 工具：`tools/decompose_cutscene.py`（五阶段流水线）＋ `tools/cutscene_template.html`（查看器）
> 样本：`录屏/带说话人录屏.mp4`（35:14）　验证：`raw/capture/wnt1_320_400.mp4`（80s）、`wnt1_338_364.mp4`（26s）
> 更新：2026-10-23

---

## 0. 这套东西的定位（先说清不是啥）

| 是 | 不是 |
|---|---|
| 从**画面 + 字幕**还原演出信息（谁、什么时候、说了什么、镜头怎么剪的） | 不是解包 CG 视频文件（过场是 Bink2，`KB2j`，ffmpeg 解不了，只能录屏） |
| 用录屏去**校验/补全**已解包的剧本与 actor | 不是重新解一遍资产 |
| 一条录屏 = 一条游玩路径 → 只能看到这条路径上播出的台词 | 不是剧本全集（分支台词不会出现在单次录屏里） |

**为什么要它**：`.ymt` 解出来的说话人有 2.2% 对不上名字、0.6% 根本不在对话资产里；剧本有 61/99 个任务缺状态机顺序。录屏是**独立证据源**，能反过来填这些洞。

---

## 1. 输入契约（什么样的录屏能用）

| 条件 | 要求 | 不满足会怎样 |
|---|---|---|
| 必须带**画面字幕** | 游戏内简中字幕，位于画面中下方 | 没有字幕就只能靠音频 VAD 切句，说话人基本拿不到 |
| 字幕文本必须在画面上（不是外挂字幕） | 硬字幕 | 外挂 `.srt` 更好——直接读文件即可，不必 OCR |
| 分辨率 | ≥ 720p（1280×720 实测够用） | 480p 字形糊，中文 OCR 错误率明显上升 |
| 帧率 | ≥ 24fps | 低于 20fps 会漏掉 0.5 秒内的快切 |
| 长宽比 | 16:9 | 其他比例要先确认字幕位置（本工具会自动探测） |
| 音频 | 有（可选） | 只影响 VAD 切句；本流水线不依赖音频 |

> **字幕位置不需要提前标定**：扫描阶段会自己找（见规则 R5）。

## 2. 九条核心规则

### R1 · 过场有黑边，操作没有 → 这是最可靠的"过场/操作"判据

**现象**：RDR2 进过场会把画面压成宽银幕，上下各留一条纯黑边（720p 下约 78px，占比 10.8%）。

**判据**：逐帧统计上下连续纯黑行数（行均值 < 6）：

```python
topb = 从第 0 行往上数连续黑行
botb = 从最后一行往下数连续黑行
cinematic = topb >= max(3, 片高*0.025) and botb >= 同值
```

**为什么用"占比"不用"像素"**：写死 8 行只对 180p 扫描分辨率成立，换成 1080p 就失效。现在按片高 2.5% 算，任何分辨率都成立。

**反例（踩过）**：
- 片头淡入的**全黑帧**会被误判成"上下全是黑边"→ 必须配合"连续段"判定：单帧黑不算，连续 ≥ 0.2 秒才算。
- 部分过场是**单侧黑边**（镜头仰拍），要求上下**同时**满足，避免误判。

### R2 · 硬切 = 归一化互相关骤降，不是"帧差大"

**现象**：直接算帧间平均绝对差（`gdiff`）会把**快速摇镜**和**人物大幅动作**全判成切镜。

**判据**（在 10fps、320×180 灰度上算）：

| 量 | 含义 | 切镜时的值 | 正常帧 |
|---|---|---|---|
| `gNCC` | 相邻帧灰度归一化互相关 | **0.0 ~ 0.3** | > 0.5（运镜也能到 0.82） |
| `gdiff` | 灰度平均绝对差 | 8 ~ 190 | 1 ~ 5 |
| `hdiff` | 8×8×8 颜色直方图 χ² | 5 ~ 280 | < 2 |

```python
硬切   = gNCC < 0.32 且 gdiff >= 1.5
大跳变 = gdiff >= 18 且 gNCC < 0.6        # 进出过场、闪白、黑场
低置信 = gNCC < 0.5 且 hdiff >= 4 且 gdiff >= 3   # 暗景切镜常落这里
再要求：score 是局部极大 + 两次切点间隔 >= 0.5 秒
```

**实测**：真切镜 `gNCC = 0.083 / 0.097 / 0.076 / 0.107`，正常帧 `0.88~0.99`。**分离度极好，且与分辨率、码率无关**。

### R3 · 运镜不是切镜（这条是最大的坑）

**反例**：23:13–23:33 是一段骑马跟拍，镜头持续平移。第一版判据（`gdiff > 阈值`）在这一段判出 **4 个假切点**，20 秒被切成 5 段。

**特征对比**：

| | 真硬切（21:56.0） | 骑马运镜（23:21.9） |
|---|---|---|
| gdiff | 9.2 | 12.3（更大！） |
| gNCC | **0.127** | **0.875** |
| hdiff | 6.6 | 7.1（也更大） |

**结论**：`gdiff` / `hdiff` 都不能单独用，**只有 `gNCC` 能区分"换机位"和"镜头在动"**。改判据后这一段切成 1 段，假切点归零。

### R4 · 暗景切镜会漏检 —— 承认它，并标出来

**现象**：木屋夜戏（21:50–22:20）画面很暗、两个机位构图接近，`gNCC` 在 **0.4~0.6** 之间抖动（噪声大），落在 0.32 阈值之上 → 漏检。

**实测**：该 30 秒窗口（21:50–22:20）人工按 0.5 秒步长逐帧数出约 **13** 个切点，自动检出 **10** 个（1310.7 / 1316.0 / 1317.8 / 1322.2 / 1326.1 / 1328.1 / 1330.1 / 1332.7 / 1335.0 / 1337.3），**召回约 77%**；漏的基本集中在 22:07–22:12 那段最暗的木屋对话。

**处理**：
1. 每个镜头带 `cut_conf: high|low`，页面和 CSV 都能看到；
2. 不为了补漏而整体降阈值——降了会把运镜吃进来（R3），**宁可少切不可错切**；
3. 需要补时，人工在查看器里按时间轴核对（有缩略图墙，一眼能看出是不是同一个机位）。

### R5 · 字幕带位置：按"白字行剖面"自动定位

**做法**（在扫描阶段顺手统计，零额外成本）：

1. 只看画面中部横条 `x ∈ [14%, 86%]`——躲开左下小地图、右下弹药 HUD；
2. 每帧统计"白字行"：该行白像素（> 200）数量在 3~90 之间；
3. 累计所有帧的行剖面 → 取有值的 **3%~97% 分位**，上下各留 6 行。

**实测**：

| 视频 | 自动定位出的小字幕带（占片高） | 说明 |
|---|---|---|
| `wnt1_320_400`（80s） | **0.75 ~ 0.87** | 与肉眼看到的字幕位置一致 |
| `wnt1_338_364`（26s） | **0.66 ~ 0.90** | 同上 |
| 样本主片（手工标定对照） | 570~610px / 720 = **0.79 ~ 0.85** | 落在上面两段之内 |

**失效**：字幕极少（< 4 行有值）时 → 回落兜底比例 `0.62 ~ 0.96`，并在 `info.band_source` 里标 `fallback`。

### R6 · 字幕是"逐字显示"的 → 一句要取多帧，取最全的那帧

**现象**：RDR2 字幕不是整句一次性出现，而是快速逐字冒出（还会重排）。抽查发现同一句在 3 个时刻 OCR 出三种结果：

```
0.45 位置：我找到一个地方，角 能遮风挡雪。 表：
0.75 位置：我找到一个地方，能 能遮风挡雪。 ：
0.95 位置：我找到一个地方，  能遮风挡雪。 ：
```

**判据**：每句在 **0.45 / 0.75 / 0.95** 三个位置各 OCR 一次，按下面打分取最高：

```python
score = 中文字数*2 + 总长*0.1 + (句末有。！？…)*2 - 数字个数*1.5
```

**副作用**：字幕切换的过渡帧会把**上一句的尾巴 + 下一句**混在一张图里 → 靠 R7 和匹配阶段消化。

### R7 · 字幕里的「名字：」是独立证据，但位置决定归属

**现象**：大部分台词显示成 `达奇：我们会出发`。这个前缀**不在本地化文本里**，只在画面上——所以它是校验 `.ymt` actor 的**独立证据源**。

**但要按位置分**：

| 位置 | 例子 | 归属 |
|---|---|---|
| 句首 | `达奇：拿上你认为有用的所有东西` | 属于**这一句** |
| 句尾 | `他很坚强而且也很聪明。 蒂莉：` | 属于**下一句**（字幕切换时名字先冒出来） |

配套规则：句尾名字 → 顺延给下一句（如果下一句自己没名字）。

**质量闸门**（否则 OCR 噪声会造出大量假冲突）：只有同时满足才认定为"强证据"：

1. 名字在**句首**；
2. 名字在角色表里**精确命中**（模糊命中不算，OCR 常把「达奇」读成「表」）；
3. 剧本匹配度 **≥ 0.9**；
4. 台词正文 ≥ 5 字。

**实测**：本样本 261 句里，18 句构成强证据 → **14 句与资产 actor 一致，4 句冲突**。4 句冲突全部是真人核过的"字幕写了 A、资产说 B"，属于可直接修的 bug 级发现。

### R8 · 译名/简称要归一，否则"一致"会被算成"冲突"

**现象**：画面字幕写「艾比盖尔」，本地化表写「阿比盖尔」；资产里存的是全名「达奇·范德林德」，覆盖表里是「达奇」。

**判据**：比对前先取「·」前的短名，再过一张别名表：

```python
NAME_ALIAS = {'艾比盖尔':'阿比盖尔', '阿比':'阿比盖尔', '莱尼':'蓝尼', ...}
一致 = 短名相等 或 一个是另一个的子串
```

**不归一的后果**：4 条真冲突会被放大成 14 条，人就不看了。

### R9 · 匹配要三级语料 + 两轮时间窗，否则短句会串任务

**三级语料**（优先级从高到低）：

| 级 | 来源 | 给了什么 | 命中阈值 |
|---|---|---|---|
| A | `export/story/beats/*.json` 的对话组 | 任务 / 对话组 / 句号 / **官方说话人** | 0.9（首轮）/ 0.6（次轮） |
| B | `export/story/mission_dialogue/*.txt`（音频库） | 该任务全部录制台词（含对话组外的过场台词），**没有说话人** | 0.66 |
| C | `beats.objectives_all` | 任务目标 / 失败条件提示 | 0.7 |

**两轮分配**（关键）：

1. **第 1 轮只认 ≥0.9 的**，用它建立"这段录屏出现了哪些任务、各自的时间窗"；
2. 只有**命中 ≥3 次**的任务才配拥有时间窗（否则一句"谢谢你"就能给别的主角任务开窗——实测会串出 8 个错误任务）；
3. **第 2 轮**只在时间窗内（±120 秒）找候选。

**效果**：改之前 80.8% 命中但混进 8 个错误任务；改之后 227/261，任务只剩 `WNT1(162) / WNT2(66)`。

**相似度不能用纯编辑距离**：OCR 常只读对半句，所以取

```
max( SequenceMatcher 比率 , 最长公共块占比 * 0.95 )
且"一方完整包含另一方（≥5 字）"直接给 0.82 + 0.16*长度比
```

## 3. 参数总表（改之前先看这张）

| 参数 | 值 | 在哪 | 依据 |
|---|---|---|---|
| 扫描帧率 | 10 fps | `SCAN_FPS` | 0.1 秒精度，够切点；再高成本线性涨 |
| 扫描分辨率 | 320×180 | `SCAN_W/H` | `gNCC` 在这个尺寸已足够稳 |
| 灰度存图 | 106×60（每 3 像素取 1） | `stage_scan` | 算 NCC / 边缘，再大只是变慢 |
| 黑边行阈值 | 行均值 < 6 | `stage_scan` | 纯黑边实测 0.7~1.0 |
| 黑边判过场 | ≥ 片高 2.5% | `lb_min` | 720p≈18px，实际黑边 78px |
| 切点 gNCC | < 0.32 | `detect_cuts` | 真切 0.08~0.25，运镜 0.82+ |
| 切点 gdiff 大跳变 | ≥ 18 | 同上 | 进出过场/闪白 |
| 切点最小间隔 | 0.5 s | 同上 | 再小会把一次切换记成多帧 |
| 字幕采样 | 2 fps | `BAND_FPS` | 一句通常 2~4 秒 |
| 字幕分组差异 | 掩码差异 > 15% | `stage_subs` | 160×24 掩码，比像素差稳 |
| 字幕带兜底 | 0.62~0.96 片高 | `BAND_REL` | 只在探测失败时用 |
| OCR 取样点 | 0.45 / 0.75 / 0.95 | `stage_subs` | 避开逐字显示 |
| 匹配首轮 | ≥ 0.9 | `stage_match` | 建时间窗 |
| 匹配次轮 | ≥ 0.6 | 同上 | 窗内补全 |
| 时间窗容差 | ±120 s | `assign()` | 任务之间有停顿/过场 |
| 任务进窗门槛 | 命中 ≥ 3 次 | `stage_match` | 挡掉偶发串任务 |
| 场景归并 | 色彩 L1/255 ≥ 0.25 | `stage_shots` | 相邻镜头换布景就分场 |
| 过场段合并 | 间隔 < 6 s | 同上 | 过场中间夹 1~2 个操作镜头不算断 |

## 4. 跑完怎么自检（这 6 条能挡住 90% 的错）

| # | 检查 | 合格线 | 怎么做 |
|---|---|---|---|
| 1 | 字幕带位置 | 落在 0.6~0.95 片高 | 看日志 `字幕带自动定位: ...` |
| 2 | 过场占比 | 剧情片一般 40%~60% | 看页面「过场时长 / 操作时长」 |
| 3 | 切点抽检 | 抽 12 个切点前后各 1 帧，看是否换了机位 | `raw/cutscene/_qa_sheet.py` 出图 |
| 4 | 台词匹配率 | ≥ 70%（剧情录屏） | 日志 `matched x/y` |
| 5 | 任务数 | 应等于这段剧情实际跨的任务数 | 日志 `missions: {...}` |
| 6 | 说话人冲突 | 应为个位数 | 页面「说话人冲突」徽标 |

**第 3 条的做法**（视觉核验，别只信数字）：抽 12 个切点，输出「切点前 0.2s / 后 0.2s」上下并排的图，人眼扫一遍——真实工作里这一步抓到过"骑马段 4 个假切点"。

## 5. 拿到新录屏怎么跑

```bash
# 一条
uv run python tools/decompose_cutscene.py --stage all --video "录屏/新片段.mp4"

# 多条（各自独立中间产物，最后合并到一个页面）
uv run python tools/decompose_cutscene.py --stage all \
    --video "录屏/A.mp4" "录屏/B.mp4" "raw/capture/C.mp4"

# 目录里所有 mp4
uv run python tools/decompose_cutscene.py --stage all --all-videos

# 只重做某一步（中间产物都在，不用从头）
uv run python tools/decompose_cutscene.py --stage match --video "录屏/A.mp4"
uv run python tools/decompose_cutscene.py --stage export --video "录屏/A.mp4" "录屏/B.mp4"
```

**耗时**（单核 CPU，35 分钟 720p 实测）：

| 阶段 | 耗时 | 说明 |
|---|---|---|
| scan | 1~2 分钟 | 一次解码拿全部帧特征 |
| shots | 秒级 | 纯 numpy 计算 |
| thumbs | 1~2 分钟 | 2fps 抽图后按镜头挑最亮的一帧 |
| band | 30 秒 | 抽字幕条 |
| subs | **10~20 分钟** | 唯一慢的：每句 1~3 次 OCR（有缓存，重跑只补新帧） |
| match + export | 10 秒 | |

**产物**：

```
raw/cutscene/<视频名>/     scan.npz / shots.json / subs.json / matched.json / band/ / thumbs/
export/cutscene/           index.html / dialogue.json+csv / shots.json+csv / summary.json
export/cutscene/videos/    <视频名>.mp4（硬链接，不占第二份空间）
export/cutscene/shots/<视频名>/  镜头缩略图
```

## 6. 已知失效场景（诚实清单）

| 场景 | 现象 | 现状 / 怎么办 |
|---|---|---|
| 暗景 + 相似构图切镜 | 漏检 2~3 个/30 秒 | 已标 `cut_conf`；靠缩略图人工补 |
| 极快蒙太奇（< 0.5 秒/镜） | 会被合并 | 需要把最小间隔降到 0.3 并接受误报，谨慎 |
| 字幕极少的录屏 | 字幕带退回兜底位置 | 看 `band_source=fallback`，必要时手工给 `band_rel` |
| 外挂字幕（非硬字幕） | 画面里抓不到字 | 这种情况应直接读 `.srt`，不要走 OCR |
| 非简中字幕 | 语料匹配全失败 | 语料是简中；换语言要换 `beats` 的 `zh` 字段 |
| 教程/UI 提示混入 | 「装填弹药。」「靠近拴马桩。」被当台词 | 归到 `ui` / `unmatched`，不影响对白统计 |
| 分支台词 | 剧本里有、录屏没出现 | 这是**正常现象**，已单独列成"缺口"清单 |
| OCR 认错人名 | 「达奇」→「表」 | 模糊名一律不当强证据（R7 闸门③） |

## 8. 一句话总结

**RDR2 过场有三条可直接利用的规律**：①过场必有上下黑边；②切镜会让相邻帧的归一化互相关骤降到 0.3 以下（运镜不会）；③字幕自带「名字：」，是校验资产 actor 的独立证据。
