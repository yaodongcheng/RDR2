## 2.5 自动定位"哪几帧有字幕"（不需要 OCR）

用纯 numpy 做判别：取画面下方裁剪区，找白像素最多的那一行——
- **文字行**：白像素中等（3~45）+ 横向跳变多（字间有缝）→ 判为字幕
- **进度条/亮边**：白像素很多但几乎连续（跳变 ≤6）→ 排除

实测（19.2 秒、0.25 秒采样 ≈ 77 帧）：

```
[有字幕] 5.5s / 5.8s / 6.0s / 6.2s   → 4 帧
扫描完成：4 帧有字幕（其余 73 帧全部排除，0 误报）
```

定位结果与人工核对一致（只有 5.26–6.21s 那句）。
这样**只需对 4 帧做字幕识别**，不必逐帧看。

## 5. 补充调查：「这句问候语能不能定位到说话人变量？」

用户追问：这是和陌生人打招呼的问候语，难道找不到这句话来定位说话人？

### 查了什么

| 检查 | 结果 |
|---|---|
| 18 个角色语音包全量枚举（`john_player` 3 942 条 / `arthur` …） | **没有**「继续努力，不是吗？」 |
| 全部 1 929 个中文文本库搜「继续努力」 | 命中 11 个库：`arthur` / `dutch` / `global` / `rhunt` / `mar5aud` / `fick1au` / `rcmpaud` / `cdt4aud` / `hmr0aud` / `ntv1aud` / 一个 ped 包 |
| `john_player.yldb`（约翰）搜「努力」 | **0 条** |
| 约翰包里的「……，不是吗？」句式 | 大量存在（`总是有事，不是吗？` / `没那么糟，不是吗？` …） |
| 英文包 `american_rel.rpf → john_player.yldb` | 有 `Keep at.` / `I'd keep at it if I was you.`，**没有** `Keep at it, ain't ya?` |

### 结论

1. **RDR2 没有"某句台词 → 说话人"的字段**。环境语音按**角色分包**（包名=角色），
   说话人是"这句话从哪个 voice bank 播出来的"，是**播放时**的属性，不是文本属性。
2. 你录的这句**不在任何角色包的 12 837 条环境台词里**（约翰 3 377 条中也没有），
   说明它是**运行时拼接**（短语 + 「，不是吗？」句式），再叠加 HUD 的 ped 显示名。
3. 因此"定位说话人变量"这件事：**变量存在，但只在运行时（ped/voice）**；
   静态层能拿到的是"哪个角色会说哪些话"，已导出成 `export/story/greetings.json`（18 角色 / 12 837 条）。

### 已落地的替代能力

- 查看器「角色语料」页签：按角色浏览 12 837 条环境台词，可搜索；
- 剧本台词中 **521 句**通过"唯一命中某角色包"直接确定说话人（`speakers.json` 的 `conf=bank`）；
- 录屏字幕（带「约翰：」前缀）仍然是最直接的运行时证据，已接入「现场采集」页签。

## 8. ★ 说话人信息到底在哪：三层结构（用你给的录屏反查出来的）

用户说明：录屏只是"辅助找出说话人的特征信息在哪"。查完的结论：

| 层 | 文件 | 内容 | 是否有"谁说的" |
|---|---|---|---|
| ① 文本层 | `<任务>aud.yldb` | 台词字符串（原文只有 `~z~我们会找到食物。`） | ❌ 无 |
| ② **对话流层** | `common/data/ai/conversations.meta` | **75 条对话流**，每条按顺序列 `SpeechContext`：第 1 句=发起者，后续=回应者 | ✅ **有（结构性的）** |
| ③ 语音层 | `john_player.yldb` / `arthur.yldb` … 按角色分包 | 每个 SpeechContext 在**说话人自己的包里**有若干候选台词 | ✅ 包名=角色 |

**所以"这句话是谁说的"= 这句话由哪个角色的语音包、在哪个 SpeechContext 下播出。**
这就是为什么：
- 环境/寒暄（打招呼）→ 分包能直接定角色（已导出 12 837 条）；
- 主线过场 → 由 conversation 资产在运行时绑定，静态文本里没有；
- HUD 的「达奇：」前缀 → 显示的是**当前播放的 ped**，不是文本字段。

## 9. 说话人绑定的"原件"找到了：`audio/conversations.rpf`

顺着"脚本只按名字创建对话"这条线（`AUDIO::CREATE_NEW_SCRIPTED_CONVERSATION(&"WNT1_BANT")`），
找到了真正的对话资产包：

```

解出：raw/conversations/out/*.ymt           18 417 个 .ymt
```

每个 `.ymt` 就是**一个对话**，里面逐句记录 **(SpeechContext, LineKey)** 配对。实例（`WNT1_INT_CABIN`）：

```
WNT1_HWAA ↔ WNT1_INT_CABIN_1
WNT1_HWAB ↔ WNT1_INT_CABIN_2
WNT1_HWCL ↔ WNT1_INT_CABIN_3     ← 这一句用了不同前缀（另一条音轨/变体）
WNT1_HWAC ↔ WNT1_INT_CABIN_4
...
WNT1_HWCK ↔ WNT1_INT_CABIN_64
```

### 这意味着什么

| 事实 | 依据 |
|---|---|
| 台词键 → 语音上下文键 的映射在对话资产里 | 上面的配对 |
| 该行由**谁**说，在资产里是 **actor 索引**（PSIN 结构），不在字符串里 | 资产内只有 context/line 两种字符串，无 ped 名 |
| HUD 显示「达奇：」用的就是这个 actor | 与录屏一致 |

## 10. 尝试解析 actor 索引（结论：静态不可解，需格式规范或运行时）

目标：从 18 417 个 `.ymt` 里读出"每句属于哪个 actor"。

已试过的手段与结果：

| 尝试 | 结果 |
|---|---|
| 在 `.ymt` 里找 ped 名（`cs_dutch_ms1` 等 12 个）的 joaat | **0 命中** |
| 找 ped 名明文 | 文件内除 `WNT1_*`（context/line）与 PSIN 分块标签外**无其它字符串** |
| 扫 u32[64] / u16[64] / u8[64] 小值数组（64=句数） | 无符合结构的数组 |
| 解 PSCH（schema 块） | 块内以 4 字节哈希表示字段名；用 names.txt **294 471 条**名做 joaat 交叉，**0 命中** |
| 结构推断（0x30 步长记录） | 实为哈希/链表结构，非逐行记录 |
| 读 `PMAP` 块 | 为"哈希 → 偏移/长度"的指针表，不含 actor 名 |

**结论**：actor 引用是 **PSIN 内部的索引**，其 schema（PSCH）用哈希表示字段名且不在游戏名表里。
没有 pso/PSIN 格式规范（或支持该格式的解析器）就无法静态读出；这一点已用上述 6 组实验证伪了所有低成本假设。
