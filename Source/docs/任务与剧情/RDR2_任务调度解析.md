# 荒野大镖客 2 · 任务调度解析

> 上一份文档回答“玩家要做什么”；这一份回答“**脚本怎么调度演员**”。
>
> 数据来自 194 个任务脚本（build 1355 反编译），解析出 **1,985 个生成调用点、27,977 次行为调用、62,175 次演出调用**。

| 指标 | 数值 |
|---|---|
| 有调度数据的任务 | 194 / 270 |
| 生成调用点 | 1,985（ped / vehicle / object / pickup / group） |
| 演员行为调用（TASK_*） | 27,977 |
| 演出调用（ANIMSCENE_*） | 62,175 |
| 可归属到目标函数的“阶段” | 324 个（覆盖 44 个任务） |

## 0. 先说明：这是什么，不是什么

| 能回答 | 不能回答 |
|---|---|
| 这一关用了哪些生成调用（ped/车/物） | 运行时**实际**刷出几个（数量在参数/表里） |
| 这一关用了哪些演员行为（走位/掩体/瞄准移动/上马） | 每个演员在**第几秒**做（静态代码没有时间轴） |
| 目标更新发生在哪个函数、附近有哪些行为 | 触发条件（哪个 volume、哪个 flag） |
| 演出场景名与调用密度 | 运行时的 actor 绑定关系 |

> 一句话：这是**静态调度画像**，不是运行时回放。要做到“第 12 秒刷 4 个敌人、第 20 秒 A 走到 B”，还需要运行时 trace 或把脚本状态机完整还原。

## 4. 局限与下一步

| 局限 | 原因 | 下一步 |
|---|---|---|
| 生成数量是调用点 | 数量在参数/静态表里，跨函数传递 | 解析 spawn 表 / 循环上界；或运行时 hook CREATE_PED |
| 行为没有时间轴 | 静态代码没有执行顺序 | 运行时 trace；或还原状态机后按状态排序 |
| 阶段只覆盖 44 个任务 | 目标键必须和函数在同一段代码里 | 用调用图把目标函数与行为函数连起来 |
| 演出只统计调用 | ANIMSCENE 绑定谁、播哪段在参数里 | 解析 ANIMSCENE 名与 actor 绑定 |

> 如果要做“第几秒刷几个敌人”，最直接的是**运行时 hook**：在 CREATE_PED / TASK_* 上打点，跑一遍任务就能得到真实时间轴。
