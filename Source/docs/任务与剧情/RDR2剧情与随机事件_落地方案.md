# 荒野大镖客 2 → 骑砍2：剧情与随机任务的落地突破方案

> 回答用户的三个问题：
> 1. 为什么现在解包出来的主线剧情"只有少数对白"、没有建设性？
> 2. 有没有更好的办法突破？
> 3. 想在骑砍2里重建 RDR2 的世界、还原主线剧情和各种随机任务，该怎么落？
>
> 本文只写**能验证的事实**和**能执行的方案**；每条数据都对应 `export/` 下的产物，可复现。
> 更新日期：2026-10-23

## 0. 一句话结论

**问题不在"解包得不够多"，而在"解出来的东西没有结构"。**

之前的产物是「任务 ID → 一串对白字符串 + 一串目标字符串」，
既没有**顺序**，也没有**谁在什么阶段说什么**，所以你看起来"只有少数对白、没法用"。

这一轮换了三件事，事情就通了：

| # | 突破 | 结果 |
|---|---|---|
| 1 | **脚本库从 164 个扩到 1639 个**（RDR3-Decompiled-Scripts build 1491.50 全量） | 主线 105 条全部有脚本，随机遭遇第一次有脚本可读 |
| 2 | **把脚本里的嵌套状态机编译成「beat 表」**（case 序号 = 播放顺序） | 124 个任务、**11 099 个 beat**、**5 250 个对白组 / 19 261 行台词**带顺序落地 |
| 3 | **想清楚"随机任务"到底是什么** | 57 个随机遭遇脚本 → 它们是**模板**（人物池 + 行为 + 武器），不是剧本，照剧本方式解永远解不出来 |

一句话：**主线要"编剧"，随机任务要"抽卡表"。两者的数据形态不同，之前用同一种方式解，所以两边都不像样。**

## 1. 之前为什么"只有少数对白"（三层原因，逐层拆）

### 1.1 第一层：脚本层是空的

之前的 `RDR2_剧情与角色覆盖审计.md` 写得很清楚：`script_rel.rpf` 用 RPF8 tag `0xC6(198)` 加密，
密钥表里没有 198 ⇒ `.ysc` 解不开 ⇒ **任务里"谁在什么时候说什么、生成谁、怎么推进"整层缺失**。
当时退而求其次：用社区反编译库补，但本地只落了 **164 个脚本**，只够主线的一部分。

没有脚本，就只剩 `missions.meta`（任务标题/简介）+ 各任务 `yldb`（对白字符串）。
**字符串是没有顺序的**——这就是"少数对白"的直接来源。

### 1.2 第二层：对白是"按组存的"，不是"按句存的"

RDR2 的字幕库 `<id>aud.yldb` 里，一段对话存成 `WNT1_BANT_1 … WNT1_BANT_6`。
之前只导了「组名 + 句数 + 第一句」，正文丢在 yldb 里没展开 →
一个 12 句的对话，你只能看到 1 句。

这次把 `_1.._N` 全部展开（按数字后缀排序，**这个顺序就是游戏里播放的顺序**），
WNT1 的对白从 **46 组 / 271 行** 变成 **77 组 / 367 行**。

### 1.3 第三层：任务不是线性的，是嵌套状态机

RDR2 主线脚本长这样（`winter1.c`，10.8 万行）：

```
外层阶段机  →  beat 运行器  →  beat 函数
                              switch (func_1346(cParam0)) {
                                case 0: 设置目标 "跟随迈卡"        → next = 1
                                case 1: ...
                                case 3: 播放对白 "WNT1_BANT"（6 句）→ next = 21
                                case 4: 播放对白 "WNT1_HITCH"       → next = 21
                              }
```

**case 的序号就是播放顺序**，每个 case 末尾用 `func_135(cParam0, N)` 推进。
之前没人拆这一层，所以拿到的是"一袋台词"，不是"一场戏"。

### 2.2 突破二：把脚本编译成 beat 表

新工具 `tools/story_compile.py`：

1. 解析 C 代码 → 函数表 / 调用图；
2. 找出**真正的 beat 函数**（判据：拿 `cParam0` 任务结构体 + 至少一个 case 会推进 + 不是 `pl_/script@` 演出场景表）；
3. 按「调用层级 → 外层 case 序号 → 内层 case 序号」排出**时序**；
4. 从每个 case 里抽出：目标（中文 + 脚本内联英文 GXT）、对白组（展开每一句）、演出场景名、生成物；
5. 语音/字幕没进 beat 的对白组，单独列为 `loose`（内容清单，不参与时序）。

产物：`export/story/beats/<ID>.json` + `<ID>.md`（可读剧本）+ `beats_index.csv`。

### 2.3 突破三：随机任务不是"剧情"，是"模板"

这是之前最大的认知偏差。

随机遭遇（路边伏击/抢劫/陷阱）**没有专属对白库**——脚本里全是
`SPEECH_PARAMS_BEAT_SHOUTED_CLEAR` 这类通用呼喝，人物从**区域人物池**里抽，
行为由 `TASK::*` 驱动。所以：

> 你永远不可能"解包出随机任务的台词"，因为它本来就没有固定台词。
> 要还原它，必须还原**模板**：什么地形、刷几个人、什么势力、拿什么枪、怎么演、结果如何。

`tools/story_encounters.py` 已经把这 57 个脚本编译成模板表（`export/story/encounters.json/.csv`）：

| 类型 | 数量 | 例子 |
|---|---|---|
| 伏击 ambush | 31 | `ambush_exc_bridge_trap`（邦联军桥头陷阱）、`ambush_bnd_sniper_attack`（狙击手）、`ambush_exc_wagon_bomb`（马车炸弹）、`ambush_inb_forest`（近亲家族林间伏击）、`ambush_odr_ride_out`（奥德里斯科帮冲出来） |
| 可发现地点 discoverable | 15 | 鬼火车、陨石雨、树屋、隐士老妇、印第安墓地、闪电树、点唱机… |
| 区域事件 event | 11 | 苹果籽木、中央联合铁路、Castor's Pond 等分阶段事件 |

每个模板带：势力、人物池大小、生成调用数、武器清单、主要行为（`TASK_*`）、事件上下文、状态机 case 数。

**这条路和主线完全不同**：主线是"写剧本"，随机遭遇是"配参数"。
在骑砍2里，前者要任务系统，后者只要一个**遭遇生成器**。

### 3.1 说话人专项结论（2026-10-23）

用户问："每一句是谁说的，游戏里都能看到，难道拿不到？"

**能看到的不是文本，是声音。** 拆到底之后的结论：

| 候选来源 | 实测 | 结论 |
|---|---|---|
| `<id>aud.yldb`（字幕库） | 条目结构 `hash(4) + 0 + node_ptr(4) + 0 + extra_ptr(4)`，node 里只有 `str_ptr + 字节长度` | **无 speaker/actor 字段** |
| 角色语音库 `arthur.yldb` / `john_player.yldb` | 不含 `WNT1_BANT_1` 这类任务键 | 只存 ambient 台词 |
| `global.yldb` 的 `JOURNAL_ENTRY_*` | 严格查表 0 命中（全 1929 个 yldb 扫哈希也 0 命中） | 日记文本不在已解语言包内 |
| 音频包 `x64/audio/sfx/PEDS_*.rpf` | 36 个条目/包，按**角色**分包（names.txt 有 8038 个 `.awc` 名）；条目以哈希命名 | 说话人只存在于**音轨**里，需要 line→stream 映射 |
| 演出编排 `anim/animscenes/script@story.rpf` | 已提取：**2 281 个 `.yas`**（如 `script@story@brt1@ig@ig5_drinking_scene@brt1_ig5_round_03.yas`） | `.yas` 是 PSIN 二进制，字符串只有 chunk 标签（PSIN/PMAP/PSCH/PSIG/STDN/HTAP），角色与台词均为编码值 |

**所以：官方没有"逐句说话人"这种文本字段。** 要达到游戏里那种"听得出是谁"，只有三条路：

1. **解 PSIN（`.yas`）**：拿到 anim scene 的 actor 绑定 + 台词事件 → 这是最正统的一条，工作量中高（需要 PSIN 结构定义）。
2. **运行时 hook**：ScriptHookRDR2 在 `AUDIO::PLAY_*_CONVERSATION` / `TASK_TALK` 上打点，直接把「ped + 台词键」写日志 → 一次跑完所有任务，准确率 100%，但需要开游戏跑一遍。
3. **人工标注**：已提供 `export/story/annotate.html`——点台词右侧名字循环切换、每段可「全设 X」、导出 `speaker_overrides.json` 后查看器自动合并。

**已做的自动推断（不是官方数据，会错）**
`tools/attr_speakers.py` 用「对话里被点名的角色 + 玩家」定 2 人，再按轮次交替；结果写进 `speakers.json` 的 `conf=infer`。
实测 WNT1_BANT（亚瑟/迈卡）4 句里 4 句正确，但 WNT1_TALK2（实为达奇/亚瑟，因台词提到“戴维”被误判）就错。
因此查看器**默认不显示推测**，需勾选「显示推测说话人」才出现，并带“（推测）”后缀。

配套已落地的内容：
- `export/story/speakers.json`：每段对话的**参与角色**（来自过场 cast）；
- 查看器「剧情回顾」页签：133 条任务的文字版回顾（简介 + 目标/对白要点 + 收尾台词），用于"演不出来时给玩家看文字"。

## 3. 还缺什么（诚实清单）

| # | 缺口 | 影响 | 补法 | 难度 |
|---|---|---|---|---|
| 1 | 61 条主线没有严格顺序 | 剧本要先人工排 | 调用图回溯 case 路径 / 人工排 | 中 |

| 5 | 语音未全量 | 想要原声就得解 `.awc` | 全量抽 `PEDS_*.rpf`（版权风险，不建议直接分发） | 中 |
| 6 | 过场动画只有 clip 数据 | 过场演出不能直接播 | 已有 ycd 解码；缺骨架（见 `RDR2_ycd动画解码.md`） | 高 |

## 4. 在骑砍2落地：三条路线，建议 C → B

### 4.1 路线对比

| 路线 | 做法 | 工作量 | 风险 | 建议 |
|---|---|---|---|---|
| **A. 全面转换** | 用 RDR2 的 12 km 大陆 + 全部 270 任务替换骑砍2 的战役 | 极大（数年） | 引擎/时代/系统全不匹配，几乎必失败 | ❌ |
| **B. 剧本化战役** | 在骑砍2 里做一个**新战役**：地图换成 RDR2 的美国西部（战略图层级），势力换帮派/平克顿/军队，任务走 QuestGraph | 大（6~12 个月） | 中 | ✅ 终态 |
| **C. 精选主线 + 遭遇包** | 先做 3~5 个标志性任务（WNT1 / 抢火车 / 圣丹尼斯银行）+ 一套随机遭遇系统 | 中（1~2 个月出 demo） | 低 | ✅ 起步 |

**为什么不能走 A**：骑砍2 的"世界"是**战略地图（2D）+ 场景实例（3D）**，不是一整块 12 km 连续地形。
你现在重建的 `continent.blend`（8.5 GB、9 百万面）在骑砍2 里**没有对应的承载层**。
正确用法是：**把它当成"关卡素材库 + 战略图底图"**，而不是"直接塞进游戏"。

### 4.2 数据契约（这是"落地"的关键，先定这四个 schema）

{
  "id": "WNT1", "chapter": 1, "title": "西部亡命之徒",
  "nodes": [

    {"n": 2, "type": "cutscene",  "anim": "pl_Arrival_Dutch", "skip": true},
    {"n": 3, "type": "combat",    "enemies": ["odriscoll"], "count": 3}

// 2) 遭遇模板：来自 encounters.json
{
  "id": "ambush_exc_bridge_trap", "kind": "ambush", "archetype": "bridge_trap",
  "faction": "confederate", "spawn": {"pool": "region_ped", "count": [3,5]},

### 4.3 骑砍2 侧怎么实现（模块划分）

| 层 | 骑砍2 里的落点 | 说明 |
|---|---|---|
| 战役层 | `CampaignBehaviorBase` + 自定义 `Campaign` | 章节推进、势力关系、赏金/声望 |
| 任务层 | `QuestBase` + `QuestManager` | 每个 beat 节点 = 一个任务阶段；`Journal` 条目 = 目标文本 |
| 场景层 | `MissionBehavior` + 触发器 | 进入体积 → 推进节点；`MissionScene` 按场景绑定表加载 |
| 对白层 | 场景内对话（自建 UI 读 JSON） | 骑砍自带对话树撑不住 6 句以上的长对话，建议自建覆盖层 |
| 遭遇层 | `MapEvent` / `EncounterBehavior` | 世界地图上按地形+势力+时间 roll 模板，进场景后按模板摆人 |
| 表现层 | 已有 408 个角色 glb + 骑砍2 骨骼重定向 | 动作要重定向到 28 骨（你已有成熟管线） |
